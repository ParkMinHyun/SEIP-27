\subsection{Workload Model and Online Duration Estimation}
\label{sec:model}

\smallskip\noindent\textbf{Modeled workload sequence.}
The controller models the Draft Sequence for capture \(i\) as ordered workloads \((k_1,\ldots,k_m)\), where each workload key \(k\) identifies a processing stage by output-size bucket and configuration.
The remaining sequence from position \(j\) is \(\mathcal{K}_{i,j}=(k_j,\ldots,k_m)\), including the mandatory encoding and saving stages.

\smallskip\noindent\textbf{Online point estimation.}
The controller estimates the duration of a modeled workload sequence \(\mathcal{K}=(k_1,\ldots,k_n)\) as
\begin{equation}
  \hat P(\mathcal{K})=\sum_{r=1}^{n}\hat p(k_r),
  \qquad
  \hat p(k)=\hat b(k)\,\gamma .
  \label{eq:point-estimate}
\end{equation}
The per-key base duration \(\hat b(k)\) is the cumulative mean of completed durations for key \(k\), each normalized by the condition factor \(\gamma\) in effect when measured, giving a transient spike no greater weight than any other observation.
The model represents short-term execution changes with a shared multiplicative factor \(\gamma\), while relative per-key costs stay stable in \(\hat b(k)\).
To estimate this shared factor, the controller takes the recency-weighted median of measured-to-base duration ratios across keys.
Using ratios prevents long-running workloads from dominating the estimate, while the median avoids cancellation between workloads that change in opposite directions.
The controller uses one decay factor for its recency-weighted histories: after each completed Draft Sequence, existing weights are multiplied by \(0.90\).
For an unseen output-size bucket, the estimator scales the slowest observed bucket of the same stage by pixel-count ratio; if that stage has no size history, zero denotes an unavailable estimate.
Together, these rules provide a common point estimate \(\hat P\) for admission and pacing.
