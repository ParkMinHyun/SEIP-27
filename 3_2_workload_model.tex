\subsection{Workload Model and Online Duration Estimation}
\label{sec:model}
Because both modules test predicted time against a remaining Capture Timeout budget, the controller estimates a Draft Sequence's remaining modeled stage time from durations observed on device and rescales it as conditions change.

\smallskip\noindent\textbf{Modeled workload sequence.}
The controller models the Draft Sequence for capture \(i\) as an ordered workload sequence \(\mathcal{K}_i=(k_1,\ldots,k_m)\), where each workload key \(k\) identifies a processing stage by output-size bucket and configuration.
From position \(j\), \(\mathcal{K}_{i,j}=(k_j,\ldots,k_m)\) denotes the remaining sequence, ending in a mandatory terminal key measured from encoding start until the Draft image is saved.

\smallskip\noindent\textbf{Online point estimation.}
The controller estimates the duration of a modeled workload sequence \(\mathcal{K}\) by summing its predicted per-key durations:
\begin{equation}
  \hat P(\mathcal{K})
  =\sum_{k\in\mathcal{K}}\hat p(k),
  \qquad
  \hat p(k)=\hat b(k)\,\gamma .
  \label{eq:point-estimate}
\end{equation}
The per-key base duration \(\hat b(k)\) is a condition-normalized cumulative mean of the durations observed for key \(k\), and \(\hat p(k)\) scales this base by the current condition factor \(\gamma\).
This cumulative base limits the influence of transient spikes by giving them no recency advantage, while the shared \(\gamma\) tracks recent execution trends across workload keys.
To estimate \(\gamma\), the controller takes the recency-weighted median of measured-to-base duration ratios across workload keys.
Using ratios prevents long-running workloads from dominating the estimate, while the median avoids cancellation between workloads that change in opposite directions.
At each update, existing observation weights are multiplied by \(0.90\) before new observations are added.
For an unseen output-size bucket, the estimator uses the previously observed bucket with the largest base duration in the same stage family as a reference and scales that duration by the ratio of the target to reference pixel counts.
If the stage family has no history, the estimate is zero, indicating a cold-start case.
Histories are cleared only after both the camera application has closed and all queued Draft Sequences have completed.
