\subsection{Workload Model and Online Duration Estimation}
\label{sec:model}

\smallskip\noindent\textbf{Modeled workload sequence.}
The controller models the Draft Sequence for capture \(i\) as an ordered workload sequence \(\mathcal{K}_i=(k_1,\ldots,k_m)\), where each workload key \(k\) identifies a processing stage by output-size bucket and configuration.
From position \(j\), \(\mathcal{K}_{i,j}=(k_j,\ldots,k_m)\) denotes the remaining sequence, ending in a mandatory terminal key measured from encoding start until the Draft image is saved.

\smallskip\noindent\textbf{Online point estimation.}
The controller estimates the duration of
\(\mathcal{K}=\mathcal{K}_{i,j}=(k_j,\ldots,k_m)\) as
\begin{equation}
  \hat P(\mathcal{K})
  =\sum_{r=j}^{m}\hat p(k_r),
  \qquad
  \hat p(k)=\hat b(k)\,\gamma .
  \label{eq:point-estimate}
\end{equation}
The per-key base duration \(\hat b(k)\) is the cumulative mean of the duration observed for key \(k\), each divided by the condition factor \(\gamma\) in effect when that sample was recorded.
This cumulative base limits the influence of transient spikes by giving them no recency advantage, while the shared \(\gamma\) tracks recent execution trends across keys.
To estimate \(\gamma\), the controller takes the recency-weighted median of measured-to-base duration ratios across keys.
Using ratios prevents long-running workloads from dominating the estimate, while the median avoids cancellation between workloads that change in opposite directions.
Each recency-weighted update multiplies existing weights by \(0.90\) before adding new observations.
For an unseen output-size bucket, the estimator scales the slowest observed bucket of the same stage family by pixel-count ratio; if that family has no history, zero denotes a cold-start case.
The resulting \(\hat P\) estimates modeled stage time for admission and pacing using histories retained while the camera application remains open.
