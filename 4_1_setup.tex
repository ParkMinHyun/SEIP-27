\subsection{Experimental Setup}
\label{sec:setup}

Table~\ref{tab:setup} summarizes the setup shared by every arm, which follows the baseline campaign of Section~\ref{sec:guard-limit}.
The evaluation reports the least and the most demanding of the conditions that campaign measured: 12MP normal capture, the production-default resolution, and 24MP capture under memory pressure, where the uncontrolled configuration times out earliest.
The 24MP label names the requested mode, since only the first one or two captures of a run are produced at that resolution and the remainder fall back to 12MP.

\smallskip\noindent\textbf{Controller configurations.}
The production static thermal guard is bypassed in every arm, so the comparison isolates runtime control rather than the level-4 threshold, and enabling the two modules independently yields four configurations.
\emph{No control} executes every optional stage and releases \texttt{captureAvailable} as soon as the framework is ready; this is what enabling the Draft Sequence's lightweight multi-frame composition would require, and it is the configuration Table~\ref{tab:timeout_index} measures.
\emph{Admission only} enforces Equation~\ref{eq:admission} at each admission point but never delays the callback.
\emph{Pacing only} delays the callback by Equation~\ref{eq:pacing} while executing every optional stage, and records the admission decisions it does not enforce, which is the audit RQ3 reads.
\emph{Full} enables both modules and is the controller of Sections~\ref{sec:admission} and~\ref{sec:pacing}.

\smallskip\noindent\textbf{Protocol and measurement.}
A run starts once the platform reports a transition to that run's target overheat level, so the starting thermal state is read from the same ordinal signal the deployed guard acts on rather than set by an external proxy.
Every run then begins a fresh camera application session, so the estimator histories of Section~\ref{sec:model}, the queue-local set \(G\), and the backlog clock all start empty and no controller state carries from one run to the next.
A recording path added for the study exports one row per capture and one per admission and pacing decision, retaining the decision-time estimates \(U\), \(\hat B_i\), and \(\hat C\), the delay \(d_i\) the decision requested, and the realized stage and Draft Sequence durations those estimates are compared against.
Deadline margins are reported as a percentage of the Capture Timeout budget rather than in absolute time, and a capture counts toward \(M\) or \(S\) only when the corresponding stage has a positive observed duration.
A 30-capture run yields 29 capture-availability transitions; pacing activation rates and \(d\) percentiles are taken over those transitions, excluding the delay associated with the final capture, which gates no further capture.
Sessions carrying a Capture Timeout label are excluded from the full-controller collection as known invalid measurements produced by a recording fault rather than observed deadline misses; runs that ended before 30 captures are otherwise retained, and each research question states the population it uses.
