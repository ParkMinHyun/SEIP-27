\subsection{Framework Integration}
\label{sec:implementation}

The framework already separates draft sequence execution from delivery of the capture-availability callback.
The controller attaches to these two decision points within the framework, preserving the HAL and application interfaces.

\smallskip\noindent\textbf{Ownership and attachment.}
The framework component that owns the single Draft worker also hosts the shared estimator.
This places admission beside the stages whose durations it measures, allowing it to read the remaining timeout window immediately before an optional stage executes.
The component that delivers \texttt{captureAvailable} has a separate lifecycle, so it requests the pacing delay through a single-method internal interface over the existing event channel.
Only the computed delay \(d_i\) crosses this interface; the estimator and its execution history remain with the Draft pipeline.

The integration adds two threads: one for callback delivery and one for watchdog fallback.
The delivery thread releases \texttt{captureAvailable} after \(d_i\), allowing the Draft worker to continue while the callback waits.
The fallback thread addresses a different constraint: an admitted optional stage cannot be cancelled once it enters native image processing.
If the watchdog expires, the fallback thread encodes and saves from the preserved original input independently of that stage.
Resources owned by the in-flight stage are released only after it finishes.
This lets fallback produce the draft image without waiting for the native operation to return.

\smallskip\noindent\textbf{Deployment scope.}
The controller identifies processing stages through workload keys, so an additional optional stage can use the same estimation and control logic once its key is defined.
Both modules learn durations from execution on the current device instead of selecting per-model timing tables or using explicit thermal-state signals in their decisions.
The controller keeps its decay factor and two-sequence reserve horizon fixed, while learning durations within each camera application session.
The controller has been integrated into the product branch and is undergoing release validation for a forthcoming Galaxy flagship smartphone line.
