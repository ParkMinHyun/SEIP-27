\subsection{Framework Integration and Instrumentation}
\label{sec:implementation}
The controller integrates at existing framework decision points, preserving the framework's ownership and execution structure without introducing new cross-layer interfaces.

\smallskip\noindent\textbf{Framework integration.}
The framework component that already owns the single Draft worker also hosts both modules and the estimator they share, and continues to execute Draft Sequences in capture order on that worker; a per-sequence hook binds the configured workload sequence to admission at each optional stage, to watchdog handling, and to model updates.
On the application-facing capture-availability path, the framework consults pacing, which serializes concurrent callbacks, and defers callback release by the computed \(d_i\).
Integration adds one scheduling thread, no additional Draft worker, and no persistent controller state, and consumes no device-state signal: overheat level, memory, and CPU are recorded for analysis only.
Beyond the shared decay factor and the two-sequence reserve horizon, it introduces no per-device constant or model-specific branch.
The evaluated build removes the static level-4 thermal guard (Section~\ref{sec:guard-limit}), so an optional stage runs at that level exactly when admission permits it; the integration has not yet shipped in a commercial release.

\smallskip\noindent\textbf{Fail-open paths.}
Every path the controller cannot serve degrades to the behavior that preceded it, and neither its Draft Sequence submission nor its delay request can be rejected under queue pressure: both are refused only after the owning component has shut down at the end of the capture session.
A rejected delay releases the callback immediately; the immediate capture-availability paths likewise bypass pacing and commit no pacing decision.

\smallskip\noindent\textbf{Instrumentation.}
Each decision records its planned remaining sequence, point and upper estimates, live budget, watchdog state, and pacing inputs, together with the resulting stage and Draft timeline.
The model's recommendation is recorded separately from the enforced action, so the evaluation can separate model decision quality from sticky demotion and watchdog enforcement.
Whether a requested delay was honored is not persisted, and pacing governs when a capture opportunity is offered rather than when the user takes it; we therefore report \(d_i\) as the delay pacing requested rather than as realized user-perceived waiting.
