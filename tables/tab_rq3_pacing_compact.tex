% Compact coordination-aware RQ3 main-paper table, single column.  The original
% RQ3 policy, selectivity, and calibration tables remain untouched as historical
% alternatives; docs/rq3-current.md is the authoritative handoff for this exhibit
% and the source of every claim limit recorded below.
%
% Sources:
%   data/rq3/estimator/outcome_matrix.csv   every cell of the matrix
%   data/rq3/estimator/summary.csv          the identity check, the two error
%                                           distributions, the repricing
%   data/rq3/policy/summary.csv             the cost figures in the note
%
% ---------------------------------------------------------------------------
% What this exhibit has to answer
% ---------------------------------------------------------------------------
% Two questions, in this order: did pacing act where the capture was actually at
% risk, and was the delay it applied the right size?  The rows answer the first
% -- they partition every analyzed decision by how much of the required delay it
% got -- and the columns answer the second in both directions.  Under-sizing is
% the Unapplied column; over-sizing is the top row, where 350 and 374
% decisions were paced although none required a delay, and the reserve error
% beside them says why.
%
% ---------------------------------------------------------------------------
% Layout: single column, and what had to go to fit
% ---------------------------------------------------------------------------
% The previous revision was a table* with eleven columns and a four-cell cost
% block.  tab_rq1_ablation.tex records an eight-column ceiling for
% \columnwidth at \scriptsize, but that ceiling is a consequence of ITS widths,
% not a hard count: what binds is the sum of the p-widths against the 252pt
% column.  Two moves bought the room here.
%
%   Condition is a spanning block label rather than a column, which frees a
%   column and its two tabcolsep units and lets every outcome label stay on one
%   line.
%
%   Every paired quantity is SPLIT into its own sub-columns under a \cmidrule
%   group -- "P50 | max" rather than "P50 / max".  This reads as more columns
%   but measures narrower, because a cell holding one number needs only that
%   number's width while "72 / 582" needs both plus a separator.  The nine
%   columns sum to 203pt where the six merged ones summed to 212pt, and the
%   grid is easier to scan: four of the six merged columns were slash pairs,
%   and a reader could not tell at a glance which slash meant which statistic.
%
% Vertical rules mark the four group boundaries only.  Every data cell holds one
% number, so ruling each column would add eight lines that separate nothing.
%
% ---------------------------------------------------------------------------
% Printed labels, and what each of them replaced
% ---------------------------------------------------------------------------
% Column one asks "What the delay covered", so all four rows answer it in the
% same register -- a noun phrase naming the part of the requirement the delay
% reached.  The word "floor" is not printed anywhere: a reader meeting "below
% the floor" has to leave the table to find out what the floor is, whereas
% mandatory and optional work are already established in Section~2.3.
%
%   None was required        d* = 0.  Was "No delay required".
%   The full requirement     d >= d*_exec.  Was "Covered in full", and before
%                            that "Covered by pacing".
%   The mandatory work       d*_mand <= d < d*_exec: the delay reached the
%                            mandatory work but not the optional work that also
%                            ran.  Was "Mandatory work covered", and before that
%                            "Left to admission" -- a name that asserted a
%                            hand-off to admission this table prints no evidence
%                            for.
%   Less than mandatory      d < d*_mand.  Was "Below the mandatory floor".
%
%   Unapplied, d* - d (ms)   was "Missing delay".  The formula sits under the
%                            word so the column defines itself.
%   Decision-time error      was "Estimator error".  Both columns are what the
%                            controller held AT THE DECISION minus what the
%                            pipeline went on to do, so the label names the
%                            instant the estimate was made rather than the
%                            machinery that made it.
%   d inside B               was "absorbed", which never said what was absorbed
%                            into what.  With B defined in the note, the symbols
%                            carry it: the share of the delay that lies inside
%                            the outstanding backlog.
%
% Units moved into the group headers -- (ms) and (%) -- so that the note needs
% no sentence about them.  That is what got the note to three lines.
%
% The following were cut:
%
%   Applied delay P50        Table~\ref{tab:rq1_end_to_end_summary} and
%                            Table~\ref{tab:rq1_ablation} already print the
%                            applied delay per condition, on a different
%                            population; printing a second per-class value under
%                            the same name invited two numbers for one quantity.
%   Per paced capture ms     The same duplication, in the cost block.
%   Runs with no pacing      "Activated (\%)" in RQ1(a) already carries
%                            selectivity.
%   Queued pricing error     Per class it tracks the backlog error to within
%                            50 ms (+27/-19, -627/-677, -1,278/-1,392), because
%                            the backlog clock IS that sum.  The relation is
%                            close to definitional, so it belongs in the RQ3
%                            prose as one correlation rather than in a column.
%
% ---------------------------------------------------------------------------
% The figure this exhibit replaced
% ---------------------------------------------------------------------------
% figures/fig_rq3_pacing_compact.tex was deleted.  Its scatter panels restated
% the class contrast the two error columns already print, and its ECDF panel
% carried one claim the table could not: the two estimators have different
% SHAPES, not just different medians.  That claim now has to be made in the RQ3
% prose from the population P05/P50/P95 listed at the foot of this file -- the
% reserve error is positive at P05 in 12MP and only mildly negative in 24MP,
% while the per-Draft pricing error straddles zero with a long left tail.  Do
% not write that the reserve error is "almost entirely above zero": its 24MP
% P05 is -129 ms, so that phrasing holds for 12MP only.
%
% ---------------------------------------------------------------------------
% Definitions (printed in the note in short form)
% ---------------------------------------------------------------------------
%   B          measured Draft backlog at the pacing decision
%   T          budget left in the deadline window at the decision
%   C          realized duration of the admitted Draft sequence
%   C_mand     the mandatory part of C: DynamicFunction, Encoding and measured
%              Draft overhead, i.e. C with the optional work admission can skip
%              removed
%   d          the applied pacing delay
%   d*         ceil( [B + 2C - max(0,T)]^+ / 2 ), the required delay
%   d*_mand    the same expression on C_mand: the mandatory floor
%   Bhat       PacingReplay.beforeBacklogMs, the controller's backlog clock
%   Chat       beforeDraftSequenceReservedDurationMs, the Draft reserve
%
% The 2C horizon is the deployed prospective model: (i) the Draft that begins
% after the pacing decision and (ii) the Draft of the next capture released by
% that delay.  Waiting one millisecond both drains one millisecond of backlog
% and shifts the next deadline by one millisecond, hence the division by two.
% A positive unapplied delay is therefore an unmet prospective reservation, not
% an observed overrun, which is why the deadline margin column is printed beside
% it: it says what the capture actually kept.
%
% ---------------------------------------------------------------------------
% The estimator error column
% ---------------------------------------------------------------------------
% Away from the max(0,.) clip -- on the 61 and 97 decisions carrying both a
% positive applied delay and a positive required delay --
%
%     d - d*  =  (Chat - C)  +  (Bhat - B) / 2
%
% holds identically.  scripts/rq3_estimator_metrics.py asserts it and it closes
% to 0.50 and 0.76 ms, which is the two ceilings in the formulas.  Each term
% owns one failure mode:
%
%   Draft reserve Chat.  CaptureAvailablePacingSession.getMaxDraftSequence-
%   DurationMs prices it at the session's observed MAXIMUM Draft duration for
%   the capture's size bucket, re-projected onto the admitted sequence.  A
%   maximum against a typical realized duration over-covers -- P50 +230 and
%   +250 ms on the decisions that needed no delay at all -- and it enters the
%   formula twice.  That is what puts 350 and 374 decisions in the top row's
%   Paced column, and it makes the over-shoot a design choice with a measured
%   price rather than an unexplained excess.
%
%   Backlog clock Bhat.  queuePacingDecision advances it by each queued Draft's
%   POINT prediction plus one learned between-node overhead.  Per Draft that is
%   nearly right (P50 +16 and +19 ms) but widely dispersed (P05 -135 and
%   -293 ms), and unlike the reserve it is SUMMED over the queue, so the
%   dispersion accumulates.  The asymmetry is the finding an SEIP reader can act
%   on: the controller already knows to price a single Draft by a conservative
%   statistic, and prices a whole queue by a central one.
%
% LIMIT -- closed loop.  Every quantity is arithmetic on the realized trace.
% The repricing in docs/rq3-current.md, the unapplied delay, and the queued
% pricing error are NOT recoverable time: a different delay changes later
% arrivals, backlog, admission, thermal state and realized Draft duration.  The
% same rule forbids rescaling the recorded delay by 0.5 or 0.75.
%
% LIMIT -- the mandatory floor.  d*_mand is a sufficient reservation condition
% reconstructed after the run, not the timeout boundary.  The 14 floor misses
% cluster in four 24MP runs, none produced an actual Capture Timeout, and their
% minimum deadline margin -- 4.39% of the budget -- is the LARGEST of any class
% in the table, which is the direct evidence that the floor is conservative.
% On the 11 that received no delay at all the controller's own online pressure
% Bhat + 2*Chat - T was non-positive (-46 to -1,729 ms), so zero was the correct
% output of the deployed formula given its inputs; correcting the backlog clock
% alone flips that sign on 11/11 and reaches the floor on 9/11
% (data/rq3/estimator/floor_zero_delay_account.csv).
%
% WHY THERE IS NO "OPTIONAL WORK SKIPPED" COLUMN.  It was printed in an earlier
% revision of this table and removed, because it could not do the job it looked
% like it was doing.  The question it appeared to answer is why 11 of the 14
% floor misses went unpaced, and the floor row already answers that without it:
% Paced 3 of 14 beside a backlog error of -1,392 ms says the backlog clock was
% 1.4 s low, and the column reads -19, -4, -677, -1,392 down the rows, so the
% mechanism is visible as a gradient rather than asserted.  The skip rate cannot
% answer it at all -- d*_mand is defined on the mandatory work, so skipping
% optional work cannot close a mandatory-floor deficit -- yet printed beside
% "Paced 3" it invites exactly that reading.
%
% Two further reasons it was the weakest column.  Demotion is session-sticky, so
% the 100% on the floor row is largely "these four runs had already entered the
% demoted regime" rather than a response to these decisions.  And at 12MP the
% flexible band's rate, 26.9%, is BELOW the 42.4% population rate: admission did
% not step in more often there, so the column argued against the coordination
% claim it appeared to support.
%
% The rates are still generated.  outcome_matrix.csv carries skipped_this_pct
% and skipped_either_pct for every class; the two-Draft rate is an observed
% action audit over the 2C horizon and must never be phrased as causal
% attribution of the next admission decision to this delay.  If a reviewer asks
% whether admission was engaged on the floor misses, the answer is 14/14 target
% Drafts demoted, and it belongs in prose with the "does not close the deficit"
% clause attached.
%
% ---------------------------------------------------------------------------
% Units, and the rule that decides them
% ---------------------------------------------------------------------------
% The Capture Timeout budget is an internal constant and must not be recoverable
% from the manuscript.  It becomes recoverable the moment one quantity is
% printed BOTH as an absolute duration and as a share of the budget, so the rule
% is per quantity, not per table: delays and estimator errors in milliseconds
% (as in the RQ1 tables), deadline margin as a share of the budget (as in RQ1's
% "Slack P5"), pacing cost as a share of the run's elapsed time.  Before adding
% a row, check which unit the quantity already uses elsewhere.
%
% ---------------------------------------------------------------------------
% Population
% ---------------------------------------------------------------------------
% Complete 30-capture runs from
% data/ablation_sampling/48U_metrics_{12MP_normal,24MP_memory}_0803_{1,2}.xlsx.
% Records affected by the known timeout-measurement error were removed as
% invalid observations, which is data-quality filtering and NOT outcome-based
% survival conditioning; no valid analyzed run experienced an actual Capture
% Timeout, and the manuscript must not describe this population as
% survival-conditioned.  Watchdog-truncated decisions lack a complete realized
% Draft duration and are excluded from the required-delay reconstruction only.
%
% The device is a Device column in Table~\ref{tab:rq1_end_to_end_summary} and is
% named in the population paragraph, so the caption does not repeat it.
%
% Regenerate with scripts/rq3_estimator_metrics.py (the matrix, the errors, the
% floor account) and scripts/rq3_policy_metrics.py (the cost figures); see
% docs/rq3-current.md for the order.
