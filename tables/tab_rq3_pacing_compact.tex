% Compact coordination-aware RQ3 main-paper table.  The original RQ3 policy,
% selectivity, and calibration tables remain untouched as historical
% alternatives; see docs/rq3-current.md, which is the authoritative handoff for
% this pair and the source of every claim limit recorded below.
%
% Sources:
%   data/rq3/estimator/outcome_matrix.csv   every cell of the matrix
%   data/rq3/estimator/summary.csv          the identity check and the repricing
%   data/rq3/policy/summary.csv             the cost block
%
% ---------------------------------------------------------------------------
% Why the table is a matrix and no longer a list of metrics
% ---------------------------------------------------------------------------
% The previous revision printed one metric per row against two condition
% columns.  Four things went wrong with that shape, and all four are structural
% rather than wording:
%
%   1. Thresholds arrived without a definition.  A row read "Paced, over 40%
%      budget left", and 40% is a band edge of the historical selectivity
%      exhibit, which this pair does not print.  Every population here is now
%      cut by the required delay itself, so the table introduces no constant a
%      reader cannot recompute from the two formulas in the caption.
%   2. Populations were not visibly nested.  79 and 140 appeared once as a
%      pressure count and again three rows later as an envelope count, and the
%      reader had to check for themselves that 53+26+0 and 83+43+14 reproduced
%      them.  The four outcomes are now the rows of one partition: the last
%      three add to the required set and all four add to the analyzed total.
%   3. The under-estimate had no cause attached.  The old table stated "backlog
%      under-estimated 14 of 14" beside an unrelated wait percentile, which
%      reads as a model-quality complaint rather than as a mechanism.  The three
%      error columns now sit on the same row as the outcome they explain, and
%      the class contrast carries the claim: the queue's accumulated pricing
%      error is +27 and +9 ms where no delay was required and -627, -930 and
%      -1,278 ms on the rows where pacing fell short.
%   4. A whole block printed "--" in the 12MP column because no 12MP decision
%      fell below the floor.  That structural zero is now one spanning cell that
%      says so, and every other cell in the matrix is a real measurement.
%
% ---------------------------------------------------------------------------
% Naming
% ---------------------------------------------------------------------------
% Every printed label uses a term the manuscript already prints elsewhere.  The
% generated CSVs and scripts/rq3_*.py keep their own column names, so this is
% the map between the two vocabularies:
%
%   printed here                 elsewhere in the repository
%   -----------------------------------------------------------------------
%   pacing decision              transition (one shot-to-shot interval; a
%                                30-capture run holds 29 of them, which is the
%                                denominator of "Activated (%)" in
%                                Table~\ref{tab:rq1_end_to_end_summary})
%   run                          burst; a complete 30-capture session, the unit
%                                counted by "Survived runs" in RQ1(a)/(b)
%   required delay               envelope, d*
%   missing delay                d* - d: potential avoided delay (flexible
%                                band), shortfall_ms (mandatory block)
%   skipped optional work        demotion (Bokeh+Filter -> Filter only ->
%                                Encoding only), which RQ2 prints as "Skipped"
%   deadline margin              realized margin; RQ1(a) prints the normalized
%                                form as "Slack P5"
%   this / next Draft            target / next
%
% ---------------------------------------------------------------------------
% Definitions
% ---------------------------------------------------------------------------
%   B          measured Draft backlog at the pacing decision
%   T          budget left in the deadline window at the decision
%   C          realized duration of the admitted Draft sequence
%   C_mand     the mandatory part of C: DynamicFunction, Encoding and measured
%              Draft overhead, i.e. C with the optional work admission can skip
%              removed
%   d          the applied pacing delay
%   d*         ceil( [B + 2C - max(0,T)]^+ / 2 ), the required delay
%   d*_mand    the same expression on C_mand: the mandatory floor
%   Bhat       PacingReplay.beforeBacklogMs, the controller's backlog clock
%   Chat       beforeDraftSequenceReservedDurationMs, the Draft reserve
%
% The 2C horizon is the deployed prospective model: (i) the Draft that begins
% after the pacing decision and (ii) the Draft of the next capture released by
% that delay.  Waiting one millisecond both drains one millisecond of backlog
% and shifts the next deadline by one millisecond, hence the division by two.
% A positive missing delay is therefore an unmet prospective reservation and not
% an observed overrun, which is why the deadline margin column is printed beside
% it: it says what the capture actually kept.
%
% ---------------------------------------------------------------------------
% The three error columns, and why they are the interesting ones
% ---------------------------------------------------------------------------
% Away from the max(0,.) clip -- on the 61 and 97 decisions carrying both a
% positive applied delay and a positive required delay --
%
%     d - d*  =  (Chat - C)  +  (Bhat - B) / 2
%
% holds identically.  scripts/rq3_estimator_metrics.py asserts it and it closes
% to 0.50 and 0.76 ms, which is the two ceilings in the formulas.  The two terms
% are the errors of two estimators the controller builds by different
% conventions, and the matrix shows that each one owns one failure mode:
%
%   Draft reserve Chat.  CaptureAvailablePacingSession.getMaxDraftSequence-
%   DurationMs prices it at the session's observed MAXIMUM Draft duration for
%   the capture's size bucket, re-projected onto the admitted sequence.  A
%   maximum against a typical realized duration over-covers -- P50 +230 and
%   +250 ms on the decisions that needed no delay at all -- and it enters the
%   formula twice.  That is what puts 350 and 374 decisions in the top row's
%   Paced column, and it makes the over-shoot a design choice with a measured
%   price rather than an unexplained excess.
%
%   Backlog clock Bhat.  queuePacingDecision advances it by each queued Draft's
%   POINT prediction plus one learned between-node overhead.  Per Draft that is
%   nearly right (pricing error P50 +16 and +19 ms) but widely dispersed (P05
%   -135 and -293 ms), and unlike the reserve it is SUMMED over the queue, so
%   the dispersion accumulates.  The Queued Draft pricing error column is that
%   sum over the Drafts occupying the pipeline ahead of the decision; it tracks
%   the backlog error at Pearson r = 0.95 and 0.88, which is what makes this a
%   mechanism and not an association.  Figure~\ref{fig:rq3_pacing_compact} plots
%   both halves.
%
% The asymmetry is the finding an SEIP reader can act on: the controller already
% knows to price a single Draft by a conservative statistic, and prices a whole
% queue by a central one.
%
% LIMIT -- the repricing.  Substituting the measured backlog into the deployed
% formula on the recorded row prices at or above the mandatory floor on 11 of
% the 14 floor misses (summary.csv, floorMissRepricedAtOrAboveFloor).  That is
% what the controller would have computed at that instant with an exact clock,
% not what the run would have done: pacing is closed-loop, so a different delay
% changes later arrivals, backlog, admission, thermal state and realized Draft
% duration.  The same rule forbids rescaling the recorded delay column by 0.5 or
% 0.75, and forbids reading the queued pricing error as recoverable time.
%
% LIMIT -- the mandatory floor.  d*_mand is a sufficient reservation condition
% reconstructed after the run, not the timeout boundary.  All 14 floor misses
% had optional work skipped on their own Draft, but because d*_mand already
% excludes optional work, that skip documents coordination rather than erasing
% the deficit.  The 14 cluster in four 24MP runs and none produced an actual
% Capture Timeout; their minimum deadline margin, 4.39% of the budget, is the
% largest of any class in the table, which is the direct evidence that the floor
% is conservative.  Rising thermal headroom over a median 4.7 s of queue
% residence remains observationally consistent with drift after the online
% decision; do not claim causality from that trace split.
%
% LIMIT -- optional work skipped.  Admission demotion is session-sticky, so
% within a run the shots after the first skip are mostly skips too: pooled over
% the analyzed decisions, this-Draft and next-Draft skips co-occur 807 and 779
% times against 2 and 5 this-Draft-only, and the 50 and 51 next-Draft-only cases
% are the onset shots.  The printed column is therefore the
% this-Draft rate alone, which needs no horizon argument.  The two-Draft rates
% are in data/rq3/estimator/outcome_matrix.csv (skipped_either_pct); they are an
% observed-action audit over the 2C horizon and must never be phrased as causal
% attribution of the next admission decision to the current delay.
%
% ---------------------------------------------------------------------------
% Units, and the rule that decides them
% ---------------------------------------------------------------------------
% The Capture Timeout budget is an internal constant and must not be recoverable
% from the manuscript.  It becomes recoverable the moment one quantity is
% printed BOTH as an absolute duration and as a share of the budget, so the rule
% is per quantity, not per table: each one appears in exactly one unit across
% the whole paper.
%
%   delay -- applied, missing, and both estimator errors
%       Milliseconds.  Table~\ref{tab:rq1_end_to_end_summary} and
%       Table~\ref{tab:rq1_ablation} already print the applied delay in ms, and
%       it is the one number a product owner reads directly.
%   deadline margin
%       Share of the budget.  RQ1(a) already prints the normalized form as
%       "Slack P5 (%)", so ms here would be the same mistake in the other
%       direction.
%   per-run pacing cost
%       Share of the run's elapsed time, which has no millisecond counterpart
%       anywhere in the manuscript.
%
% Before adding a row, check which unit the quantity already uses elsewhere; do
% not introduce a second one for it.
%
% ---------------------------------------------------------------------------
% Population
% ---------------------------------------------------------------------------
% Complete 30-capture runs from
% data/ablation_sampling/48U_metrics_{12MP_normal,24MP_memory}_0803_{1,2}.xlsx:
% 70 and 69 runs, 1,920 and 1,861 analyzed pacing decisions.  Records affected
% by the known timeout-measurement error were removed as invalid observations,
% which is data-quality filtering and NOT outcome-based survival conditioning;
% no valid analyzed run experienced an actual Capture Timeout, and the
% manuscript must not describe this population as survival-conditioned.
% Watchdog-truncated decisions lack a complete realized Draft duration and are
% excluded from the required-delay reconstruction only.
%
% The device is a Device column in Table~\ref{tab:rq1_end_to_end_summary} and is
% named in the population paragraph, so the caption does not repeat it.
%
% Regenerate with scripts/rq3_estimator_metrics.py (the matrix, the errors and
% the repricing) and scripts/rq3_policy_metrics.py (the cost block); see
% docs/rq3-current.md for the order.

  \caption{RQ3: what each pacing decision required, what it got, and where the
  difference came from.  On measured inputs a decision's \emph{required delay}
  is $d^{*}=\ceil{[B+2C-\max(0,T)]^{+}/2}$, with $B$ the measured Draft backlog
  at the decision, $C$ the realized duration of the admitted Draft sequence and
  $T$ the budget left in the deadline window; the \emph{mandatory floor}
  $d^{*}_{\mathrm{mand}}$ is the same expression with the optional work
  admission can skip removed from $C$.  The four outcomes partition every
  analyzed decision --- 1{,}920 and 1{,}861, of which 411 and 471 were paced ---
  and the last three partition the decisions that required a delay (79 and 140);
  applied delay is a median over each row's paced decisions.
  The $2C$ horizon reserves for two Drafts, the one that begins after the
  decision and the next capture's released by that delay, so a positive
  \emph{missing delay} is an unmet prospective reservation and not an observed
  overrun: on the rows that left part of it to admission the optional work more
  often ran to completion, and the capture still met its deadline with at least
  1.91\% and 0.51\% of the budget in hand.  No analyzed run experienced a
  Capture Timeout.  The three error columns
  are the exact decomposition $d-d^{*}=(\hat{C}-C)+(\hat{B}-B)/2$, which closes
  to $0.8$\,ms on the 61 and 97 decisions carrying both a positive applied and a
  positive required delay.  The Draft reserve $\hat{C}$ is the session's
  observed \emph{maximum} Draft duration for the capture's size bucket, so it
  over-covers, and that is why pacing also fires on 19.0\% and 21.7\% of the
  decisions that needed none.  The backlog clock $\hat{B}$ instead sums a
  \emph{point} price over the queued Drafts: the last column is the accumulated
  error of those prices, it tracks the backlog error at Pearson $r=0.95$ and
  $0.88$, and it is what separates the two short-fall rows from the rest of the
  table.  Repricing the deployed formula on the recorded row with the measured
  backlog reaches the floor on 11 of the 14 misses --- an instantaneous
  repricing, not a claim about how the run would have gone, since pacing is
  closed-loop.  Figure~\ref{fig:rq3_pacing_compact} plots both estimator
  errors.}
