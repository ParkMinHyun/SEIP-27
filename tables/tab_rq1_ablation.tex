% RQ1(b): Two-factor controller ablation across four stress conditions.
% This is the second RQ1 table: RQ1(a) characterizes the full controller across
% starting levels, and this one isolates what each control loop contributes.
%
% Reviewer-facing structure:
%   - Admission and Pacing remain the two axes of a factorial design; the 2x2 is
%     unrolled into four rows per condition so that four conditions fit one
%     table.
%   - S(30) alone is not reported.  An arm can trivially reach zero timeouts by
%     discarding optional Draft work or by pacing arbitrarily slowly, so each
%     row also reports what the arm preserved (M+S) and what it charged the user
%     (Sigma delay).  This is the column set that answers the "trivial solution"
%     objection.
%   - Failure timing (E/M) differentiates the arms that never complete 30
%     captures, which a timeout-only table would render indistinguishable.
%
% Condition definition:
%   Each condition is one (capture condition, starting overheat level) pair.
%   12MP normal and 24MP memory pressure are each reported at starting levels
%   3 and 4, the regime where the deployed static guard is closest to its
%   decision boundary and where the baseline already fails.
%   The 24MP workbooks are a requested-mode label: only the first one or two
%   captures are 24MP and the remainder are 12MP.
%
% Layout:
%   Single-column \begin{table}, about half a page.  Compression relative to the
%   earlier full-width version, with no loss of reported quantity:
%     - the separate N column is dropped, because N is the denominator of S(30);
%     - the S(30) percentage is dropped, because the fraction carries it;
%     - E and M share one "E/M" column;
%     - the Admission and Pacing On/Off columns are dropped entirely.  They
%       restated what the Configuration name already says: "Admission only" is
%       exactly A-on/P-off.  The four configuration names, in the order given,
%       still walk the 2x2, so the factorial survives without two columns of
%       duplicated marks.
%   Natural column sizing left the table about 201pt wide inside a 252pt
%   \columnwidth, and spending the whole 51pt remainder on one uniform
%   \tabcolsep only widened the gaps while leaving the narrow-valued columns
%   looking squeezed.  The widths are therefore set per column; see the note
%   above the tabular for the measured floors and the fill arithmetic.  A
%   re-added column has to come out of those widths, so re-measure rather than
%   assuming there is slack.
%
% Belongs in the RQ1 prose, not in this note (it was moved out to keep the
% table near half a column): M+S and Sigma-d are reported because S(30) alone is
% trivially maximized either by discarding optional work or by pacing without
% bound, and the two single-component arms occupy exactly those two degenerate
% corners.  Admission only reaches 100% S(30) in two of the four conditions
% while retaining the least optional work of any arm; Pacing only retains all
% optional work but has low survival.
%
% Printed label vs metric name:
%   The guide names the metrics S(30), M+S and Sigma-d.  This table prints the
%   first as "Survived runs" and gives the two group headers the RQ1(a) names,
%   "Completion" and "Pacing cost", so a reader meets words rather than symbols
%   in the header and the two RQ1 tables use one vocabulary.  The symbols are
%   kept in the note, so the mapping to the guide stays explicit.  If these are
%   renamed again, docs/rq1-rq3-metrics-guide.md section 4.3 must follow.
%
% Column definitions (docs/rq1-rq3-metrics-guide.md, sections 3.2--3.5, 4.3):
%   S(30)    runs reaching 30 captures with no Capture Timeout, over the number
%            of included runs after run reconstruction and cross-workbook dedup
%   E / M    earliest / median first-timeout capture index; M is printed only
%            when at least half the runs in the cell timed out, otherwise the
%            median is censored and shown as --
%   Slack P5 per-run inclusive 5th percentile of 100 * timeoutMarginMs /
%            captureTimeoutMs, macro-averaged over the runs that reached 30
%            captures with no Capture Timeout; censored when the cell has none.
%            Two deliberate departures from the earlier pooled form:
%              - per run, then averaged.  Pooling every capture of every run let
%                the runs that survived longest dominate the cell, which also
%                made this column weight its runs differently from M+S in the
%                next column, and M+S is macro-averaged.
%              - survivors only.  A run that ends at its first timeout puts
%                exactly one negative margin in the pool, so the count of
%                negatives was pinned to N while the pool size was N times the
%                mean surviving length.  The percentile therefore landed inside
%                the overruns whenever that mean fell below about 20 captures,
%                and the printed sign tracked run length rather than deadline
%                safety.  In the current 12MP/Lv3 Pacing-only data, 9 of 11 runs
%                time out, yet pooling all captures still gives +1.6% because
%                the nine terminal overruns are only 4.1% of the 217 samples.
%                Failure severity now has its own column instead.
%   Overrun  median over the runs that timed out of -timeoutMarginMs at the
%   P50      first timeout, in ms; censored when no run in the cell timed out.
%            Reported in ms rather than as a percentage so failure magnitude is
%            directly readable; the current cells range from 86 to 574 ms.
%   M+S      per-run rate of (bokehCompleted && filterCompleted) over the first
%            30 captures, macro-averaged across runs
%   Sigma d  median across runs of the delay accumulated in the run
%            (RQ3Summary.totalDelayMs); structurally 0 when the pacer is off
%
% Sources per cell -- all four arms now live in this repository, so the table no
% longer depends on a path in the private implementation clone.  Values are read
% from data/ablation_sampling/ (the N=10-balanced copy; the No-control,
% Pacing-only and Admission-only workbooks there are byte-for-byte copies of
% data/ablation_original/, which stays the untouched source of record):
%   No control:      48U_metrics_12MP_normal_baseline_0803.xlsx
%                    48U_metrics_24MP_memory_baseline_0803.xlsx
%   Pacing only:     48U_metrics_12MP_normal_pacing_only_0803.xlsx
%                    48U_metrics_24MP_memory_pacing_only_0803.xlsx
%   Admission only:  48U_metrics_12MP_normal_admit_only_0803.xlsx
%                    48U_metrics_24MP_memory_admit_only_0803.xlsx
%   Full:            48U_metrics_12MP_normal_0803_{1,2}.xlsx
%                    48U_metrics_24MP_memory_0803_{1,2}.xlsx
%
% Recomputation notes:
%   - Values are recomputed directly from the workbooks with the guide's run
%     reconstruction rule.  The 12MP Full rows still reproduce the Lv3 and Lv4
%     rows of Table~\ref{tab:rq1_controller_behavior} exactly, which validates
%     the pipeline.
%   - The Full arm now pools BOTH parts of each condition's collection, which is
%     the run set Table~\ref{tab:rq1_controller_behavior} has always used, and
%     reads the balanced copy in data/ablation_sampling/.  The earlier version of
%     this table read only the first part of one workbook, so its Full cells
%     rested on 10/10/7/6 runs; pooling gives 12/14/11/10 and the N=10 balancing
%     protocol then levels every cell to ten.  The other three arms are unchanged
%     and reproduce their previous values exactly.
%     Full cells on the unbalanced pooled source, for reference:
%       12MP Lv3  12/12  Slack 4.7  M+S 53.6  Sigma-d 3.2
%       12MP Lv4  14/14  Slack 6.9  M+S 53.1  Sigma-d 4.5
%       24MP Lv3  11/11  Slack 6.1  M+S 43.6  Sigma-d 4.1
%       24MP Lv4  10/10  Slack 8.5  M+S 41.7  Sigma-d 1.4
%     The 12MP Lv3/Lv4 gap is the bimodality the balancing protocol prunes; see
%     data/ablation_sampling/README.md before quoting either number.
%   - The two Pacing-only cells with 11 and 13 runs were NOT balanced.  Only the
%     Full arm was in the balancing scope, so those denominators stay as
%     collected and the design remains uneven across arms within a condition.
%   - The predeclared per-cell exclusion is retired.  It removed one 24MP/Lv3
%     Full session containing a Capture Timeout, and the guide flagged that it
%     could not be applied symmetrically.  The data/ablation_original Full exports contain
%     no Capture-Timeout session at all, so nothing is excluded here.  BUT SEE
%     THE COLLECTION GAP BELOW -- that is not the same as none having occurred.
%   - M and S retention is measured by EXECUTION (the node has a positive
%     observed duration), not by the legacy Completed flag.  ReplayNotes
%     "Recommendation vs execution" states that Completed additionally requires
%     recommendedAdmit = true, so in the two forced-execution arms it reports
%     work that demonstrably ran as not completed: it prints 91.0/82.9 (12MP) and
%     84.3/69.5 (24MP) for No control, where the nodes in fact ran on every
%     capture.  The 24MP No-control cells previously carried those two legacy
%     values and now read 100.0 like the other three No-control/Pacing-only
%     cells.  The distinction does not arise in the admission-on arms, where the
%     two definitions agree.
%   - One consequence to state if a reviewer diffs the two RQ1 tables: the 24MP
%     Lv4 Full M+S is 41.7 here and 39.3 in
%     Table~\ref{tab:rq1_controller_behavior}, over the same ten runs.  That
%     table follows the exporter, which drops the watchdog-truncated prefix of
%     one run from the completion denominator; this table keeps every capture.
%   - The Pacing-only rows use the workbooks' includedForRq1 manifest.  In
%     particular, 12MP/Lv4 Run 21 is an incomplete, non-timeout run and is not
%     included in that cell's denominator.
%   - In the Admission-only collection, pacing decisions were left enabled for
%     observation but not applied to shutter cadence.  Median shot-to-shot on the
%     transitions carrying a positive recorded delay (449 ms in 12MP, 886 ms in
%     24MP) matches the unpaced median (434 and 839 ms) and is far below the
%     recorded delay itself (median 1,709 and 1,080 ms), so those fields are
%     shadow outputs and Sigma d is structurally 0 for this arm.  The baseline
%     workbooks behave the same way; the 24MP baseline records no pacing decision
%     at all.
%   - The 24MP baseline workbook predates RQ1Runs, so its 59 runs are
%     reconstructed by ppSequenceId reset; all relevant Lv3/Lv4 runs are valid
%     timeout or 30-capture sessions.
%
% COLLECTION GAP -- resolve before submission:
%   The Full exports are missing the run ids that the RQ3 notes identify as the
%   Capture-Timeout sessions of this arm (12MP run 9; 24MP runs 35 and 36).
%   RQ1Runs jumps over them.  The Full denominators above therefore count only
%   the sessions present in the export, and "12/12" is not by itself evidence
%   that no attempt timed out.  Either re-export the arm without that filter, or
%   state the number of excluded sessions in the caption.  The other three arms
%   retain their timeout sessions, so the comparison is conservative against the
%   Full arm only in the sense that its denominator is smaller, not larger.
%
% DATA BALANCE NOTE:
%   Fourteen of the sixteen cells now hold N=10.  The two exceptions are
%   Pacing-only at 12MP/Lv3 (11) and 24MP/Lv4 (13), which were outside the
%   balancing scope.  Either extend the protocol to them or state the remaining
%   imbalance; a 2x2 factorial read across a row still compares 10 against 11 or
%   13 in those two conditions.
%   All workbooks carry the 0803 campaign label and the same policy label
%   (ReplayScope: RECORDED_RUNTIME / FACTUAL_RECORDED_TARGET / M+S).
%
