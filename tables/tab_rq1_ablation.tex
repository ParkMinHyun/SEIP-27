% RQ1(b): Two-factor controller ablation across four stress conditions.
% This is the second RQ1 table: RQ1(a) characterizes the full controller across
% starting levels, and this one isolates what each control loop contributes.
%
% Reviewer-facing structure:
%   - Admission and Pacing remain the two axes of a factorial design; the 2x2 is
%     unrolled into four rows per condition so that four conditions fit one
%     table.
%   - S(30) alone is not reported.  An arm can trivially reach zero timeouts by
%     discarding optional Draft work or by pacing arbitrarily slowly, so each
%     row also reports what the arm preserved (M+S) and what it charged the user
%     (Sigma delay).  This is the column set that answers the "trivial solution"
%     objection.
%   - Failure timing (E/M) differentiates the arms that never complete 30
%     captures, which a timeout-only table would render indistinguishable.
%
% Condition definition:
%   Each condition is one (capture condition, starting overheat level) pair.
%   12MP normal and 24MP memory pressure are each reported at starting levels
%   3 and 4, the regime where the deployed static guard is closest to its
%   decision boundary and where the baseline already fails.
%   The 24MP workbooks are a requested-mode label: only the first one or two
%   captures are 24MP and the remainder are 12MP.
%
% Layout:
%   Single-column \begin{table}, about half a page.  Compression relative to the
%   earlier full-width version, with no loss of reported quantity:
%     - the separate N column is dropped, because N is the denominator of S(30);
%     - the S(30) percentage is dropped, because the fraction carries it;
%     - E and M share one "E/M" column;
%     - the Admission and Pacing On/Off columns are dropped entirely.  They
%       restated what the Configuration name already says: "Admission only" is
%       exactly A-on/P-off.  The four configuration names, in the order given,
%       still walk the 2x2, so the factorial survives without two columns of
%       duplicated marks.
%   Natural column sizing left the table about 201pt wide inside a 252pt
%   \columnwidth, and spending the whole 51pt remainder on one uniform
%   \tabcolsep only widened the gaps while leaving the narrow-valued columns
%   looking squeezed.  The widths are therefore set per column; see the note
%   above the tabular for the measured floors and the fill arithmetic.  A
%   re-added column has to come out of those widths, so re-measure rather than
%   assuming there is slack.
%
% Belongs in the RQ1 prose, not in this note (it was moved out to keep the
% table near half a column): M+S and Sigma-d are reported because S(30) alone is
% trivially maximized either by discarding optional work or by pacing without
% bound, and the two single-component arms occupy exactly those two degenerate
% corners.  Admission only reaches 100% S(30) in two of the four conditions
% while retaining the least optional work of any arm; Pacing only retains all
% optional work but has low survival.
%
% Printed label vs metric name:
%   The guide names the metrics S(30), M+S and Sigma-d.  This table prints the
%   first as "Survived runs" and gives the two group headers the RQ1(a) names,
%   "Completion" and "Pacing cost", so a reader meets words rather than symbols
%   in the header and the two RQ1 tables use one vocabulary.  The symbols are
%   kept in the note, so the mapping to the guide stays explicit.  If these are
%   renamed again, docs/rq1-rq3-metrics-guide.md section 4.3 must follow.
%
% Column definitions (docs/rq1-rq3-metrics-guide.md, sections 3.2--3.5, 4.3):
%   S(30)    runs reaching 30 captures with no Capture Timeout, over the number
%            of included runs after run reconstruction and cross-workbook dedup
%   E / M    earliest / median first-timeout capture index; M is printed only
%            when at least half the runs in the cell timed out, otherwise the
%            median is censored and shown as --
%   Slack P5 per-run inclusive 5th percentile of 100 * timeoutMarginMs /
%            captureTimeoutMs, macro-averaged over the runs that reached 30
%            captures with no Capture Timeout; censored when the cell has none.
%            Two deliberate departures from the earlier pooled form:
%              - per run, then averaged.  Pooling every capture of every run let
%                the runs that survived longest dominate the cell, which also
%                made this column weight its runs differently from M+S in the
%                next column, and M+S is macro-averaged.
%              - survivors only.  A run that ends at its first timeout puts
%                exactly one negative margin in the pool, so the count of
%                negatives was pinned to N while the pool size was N times the
%                mean surviving length.  The percentile therefore landed inside
%                the overruns whenever that mean fell below about 20 captures,
%                and the printed sign tracked run length rather than deadline
%                safety.  In the current 12MP/Lv3 Pacing-only data, 9 of 11 runs
%                time out, yet pooling all captures still gives +1.6% because
%                the nine terminal overruns are only 4.1% of the 217 samples.
%                Failure severity now has its own column instead.
%   Overrun  median over the runs that timed out of -timeoutMarginMs at the
%   P50      first timeout, in ms; censored when no run in the cell timed out.
%            Reported in ms rather than as a percentage so failure magnitude is
%            directly readable; the current cells range from 86 to 574 ms.
%   M+S      per-run rate of (bokehCompleted && filterCompleted) over the first
%            30 captures, macro-averaged across runs
%   Sigma d  median across runs of the delay accumulated in the run
%            (RQ3Summary.totalDelayMs); structurally 0 when the pacer is off
%
% Sources per cell:
%   No control:
%     SM-S948U_metrics_12MP_normal_baseline_0803.xlsx
%     SM-S948U_metrics_24MP_memory_baseline_0803.xlsx
%   Admission only:
%     SM-S948U_metrics_12MP_normal_admit_only_0803.xlsx
%     SM-S948U_metrics_24MP_memory_admit_only_0803.xlsx
%   Pacing only:
%     SM-S948U_metrics_12MP_normal_pacing_only_0803.xlsx
%     SM-S948U_metrics_24MP_memory_pacing_only_0803.xlsx
%   Full:
%     ML/data/0803_FULL/SM-S948U_metrics_12MP_normal_0803.xlsx
%     ML/data/0803_FULL/SM-S948U_metrics_24MP_memory_0803.xlsx
%
% Recomputation notes:
%   - Values were recomputed directly from the workbooks with the guide's run
%     reconstruction rule.  The 12MP Full rows reproduce the Lv3 and Lv4 rows of
%     Table~\ref{tab:rq1_controller_behavior} exactly, which validates the
%     pipeline.
%   - The 0803 Pacing-only rows use the workbooks' includedForRq1 manifest.  In
%     particular, 12MP/Lv4 Run 21 is an incomplete, non-timeout run and is not
%     included in that cell's denominator.
%   - In the 0803 Admission-only collection, pacing decisions were left enabled
%     for observation but not applied to shutter cadence.  Actual shot-to-shot
%     intervals remain below recorded delay values, so those fields are shadow
%     outputs and Sigma d is structurally 0 for this arm.
%   - The 0803 baseline workbooks likewise retain controller calculations for
%     observation, but neither admission nor pacing is applied.  The table uses
%     actual completion and cadence, and Sigma d is structurally 0.  The 24MP
%     workbook predates RQ1Runs, so its 59 runs are reconstructed by ppSequenceId
%     reset and joined positionally to RQ3Summary; all relevant Lv3/Lv4 runs are
%     valid timeout or 30-capture sessions.
%
% DATA BALANCE NOTE:
%   Arms are unbalanced (N ranges from 6 to 13 across the observed cells),
%   although all accessible workbooks now carry the 0803 campaign label.
%   Report the imbalance or apply a predeclared balancing protocol.
%
% Implementation reference inspected at commit:
% 99aae0af8c3fa1ceb784083446e83c40d0fb917f

    The four configurations of a condition are the Admission\,$\times$\,Pacing
    $2{\times}2$: neither loop, pacing only, admission only, and both.
    \textbf{Survived runs} (\(S(30)\) in the metrics guide): runs completing 30
    captures without Capture
    Timeout, over included runs.  \textbf{E/M}: earliest and median
    first-timeout capture index, censored (--) when fewer than half the runs
    time out.  \textbf{Slack~P5}: each run's own fifth percentile of the
    per-capture deadline margin, normalized by the Capture Timeout deadline and
    macro-averaged over the runs that survived; censored (--) when no run in the
    cell survived, because a run that ends at its first timeout contributes only
    that one overrun and a pooled percentile would then report failure severity
    instead of lower-tail safety.  \textbf{Overrun~P50}: median, over the runs
    that did time out, of how far past the deadline the first timeout ran; it
    carries the failure severity that Slack~P5 no longer absorbs, and is
    censored where no run timed out.  \mbox{\boldmath$M{+}S$}: macro-averaged
    per-run rate of completed multi-frame and single-frame optional Draft
    processing.  \mbox{\boldmath$\Sigma d$}: median accumulated pacing delay per
    run, structurally zero when the pacer is off.  24MP is a requested-mode
    label: only the first one or two captures are 24MP.  The Full 24MP/Lv3 cell
