% RQ2 results from the balanced Full-controller arm of this repository and the
% always-admit audit on one device.
% Each capture contributes at most one selected decision per optional-work
% group: Multi-frame = Bokeh; Single-frame = Filter.
%
% The Controller-enforced cells come from the balanced Full arm,
% data/ablation_sampling/48U_metrics_<condition>_0803_{1,2}.xlsx, with both parts
% pooled, runs delimited by a ppSequenceId reset, identical run signatures
% counted once and shots after 30 excluded: 70 runs / 2,100 captures at 12MP
% normal and 73 runs / 2,116 captures at 24MP memory pressure.  Two 24MP captures
% carry no Filter decision, which is why the Single-frame denominator is 2,114.
% Regenerate with scripts/rq2_admission_metrics.py.
%
% This arm replaces the earlier unbalanced 0727 pool, and the two are not
% directly comparable: the Full arm holds ten runs at each starting overheat
% level Lv0--Lv6, whereas the 0727 pool was weighted towards the hot levels.
% Standardizing on an equal weight per level, the Multi-frame admit rate moves
% 72.1% -> 59.9% at 12MP and 56.0% -> 60.5% at 24MP, so the change is a change in
% measured behaviour and not only in the level mix.
%
% The Full export contains no Capture-Timeout session -- the collection gap
% recorded in docs/rq1-rq3-metrics-guide.md section 4.3.1 -- so the observed
% safety cells characterize only the sessions present in that export.  The 0727
% cells were filtered the same way, by dropping timeout-bearing runs.
%
% These cells inherit the balancing protocol of data/ablation_sampling/README.md,
% whose deviation score reads reported outcomes and is therefore not
% outcome-neutral.  Against the untrimmed data/ablation_original the trim moves
% the Multi-frame admit rate 63.1% -> 59.9% at 12MP and 60.2% -> 60.3% at 24MP,
% and the Single-frame rate 92.2% -> 92.2% and 85.1% -> 84.7%; only the 12MP
% Multi-frame cell moves by more than half a point.
%
% The all-decision audit reports factual feasible/unsafe outcomes crossed with
% the fresh shadow-model admit/skip decision before session-sticky demotion.
% The median effect uses all shadow-model skips in the corresponding factual class
% and is normalized by the internal product Capture Timeout deadline, whose
% value is not reported.
% The Always-admit cells pool two Pacing-only sources.  Runs are reconstructed
% identically in both: split on a ppSequenceId reset, identical run signatures
% counted once, shots after 30 excluded.  No run signature is shared across the
% two campaigns, so the pools are disjoint.
%
% (a) 0729: 659 captures from 34 unique runs in
% 48U_metrics_12MP_normal_0729_PacingOnly_{1,2}.xlsx -- updated workbook 1
% contains all 22 runs in workbook 2 plus 12 additional runs -- and 827 captures
% from 53 included runs in 48U_metrics_24MP_memory_0729_PacingOnly_{1,2}.xlsx,
% where source run 16 of workbook 1 was invalid/incomplete and excluded.
%
% (b) 0803: a starting-overheat-level subset of
% data/ablation_sampling/48U_metrics_<condition>_pacing_only_0803.xlsx.  At 12MP
% normal this adds every Lv1 and Lv2 run (2 and 1) plus the Lv4 runs carrying no
% unsafe-admitted decision, which is all 11 Lv4 runs, for 14 runs / 223
% captures; Lv3 was not drawn.  At 24MP memory pressure it adds every Lv0, Lv1
% and Lv2 run (3, 1 and 3), for 7 runs / 169 captures; Lv3 and Lv4 were not
% drawn.  Pooled totals are 882 decisions per group at 12MP and 996 Multi-frame
% / 986 Single-frame at 24MP, the Single-frame shortfall being captures that
% carry no Filter decision.
%
% The 0803 draw is level-selected, not outcome-neutral, and this must be stated
% wherever the cells are discussed.  At 12MP the Lv4 no-unsafe-admit criterion
% excluded nothing, since all 11 candidates already satisfied it.  At 24MP,
% however, every unsafe-admitted decision in the 0803 source sits in the
% undrawn Lv4 band (runs 6, 19 and 23; five decisions), so the level rule alone
% removes the entire unsafe-admitted population of that source.  A Lv3--Lv4
% sensitivity pass is owed before these cells are reported as evidence.
%
% Both campaigns share the same median captureTimeoutMs deadline D = 7000 ms,
% so the margin and overrun medians are normalized consistently across the pool.
% Regenerate the Always-admit columns with scripts/rq2_audit_pool.py, which owns
% the level-selection rule; `python scripts/rq2_audit_pool.py runs` prints the
% per-run census it draws from, including the runs it holds back.
% Shadow model decision = afterModelAdmit; factual cost
% C = draftEndUptimeMs - nodeStartUptimeMs, the suffix as executed.
%
% The label is deliberately a measurement.  RQ2 scores the model's judgement on
% the decision it made, so the audit build forcing every optional node is part
% of the condition being measured, not an error to net out.  Netting it out
% would answer a different question -- was the whole decision set safe end to
% end -- and would read as moving the metric in the model's favour.  That
% question is answered per decision in
% Figure~\ref{fig:rq2_unsafe_spike_anatomy}, which marks, for each unsafe-admitted
% decision, which shipped safeguard would have prevented the overrun.
%
% For reference, on the earlier 0729-only pool, honouring the model's own skips
% on both the cost and the budget moved this block to:
%   12MP Multi   623 (96.4%) / 23 (3.6%)  +3.0%   3 (23.1%) / 10 (76.9%)  -1.4%
%   12MP Single  630 (99.4%) / 23 (3.6%)  +4.0%   0 (0.0%)  /  6 (100.0%) -4.5%
%   24MP Multi   729 (91.0%) / 72 (9.0%)  +3.7%   0 (0.0%)  / 26 (100.0%) -2.9%
%   24MP Single  752 (92.4%) / 62 (7.6%)  +5.4%   0 (0.0%)  / 13 (100.0%) -1.5%
% It lowers the unsafe-admit counts and raises the unnecessary-skip counts by
% the same act, so it is recorded here rather than reported as the headline.
% Those four lines have not been recomputed on the pooled set.
%
% Regenerate with data/rq2_spike_anatomy.mjs in the ML implementation
% repository.
%
% Every audit count carries the share of its own factual class, so the two
% Feasible-work cells sum to 100% and the two Unsafe-work cells sum to 100%.
%
% ---------------------------------------------------------------------------
% Why this is two stacked blocks and not one wide row
% ---------------------------------------------------------------------------
% Earlier revisions printed a full-width table* whose header put "Controller-
% enforced runs" and "Always-admit model audit" side by side over eleven
% columns, with Condition and Group as two leading columns repeated down every
% row.  Three problems, all fixed by the split, which follows
% tables/tab_rq3_pacing_summary.tex:
%
%   1. The two halves are DIFFERENT POPULATIONS.  (a) is the balanced Full arm;
%      (b) is a disjoint Pacing-only pool with its own denominators (882 per
%      group at 12MP, 996 / 986 at 24MP) and its own selection caveat.  Printed
%      on one row they read as one decision set measured two ways, which is the
%      single most misleading thing this table could do.  As two blocks with
%      their own headings each population is stated where its numbers are, which
%      is the rule AGENTS.md states for the RQ3 table and applies here verbatim.
%   2. Condition stopped being a column.  It is a spanning block label -- 12MP,
%      normal and 24MP, mem. pressure -- exactly as in the RQ3 table, so both
%      blocks lose a \multirow column and Group becomes the row label.  That is
%      what lets an eleven-column table* become two blocks inside \columnwidth.
%   3. The stacked \makecell cells are gone.  "59.9%" over "[1,258 of 2,100]"
%      needed two lines and a bracket convention; "$n$ | admitted" as two
%      sub-columns under one \cmidrule group prints the same two numbers on one
%      line each, which is the RQ3 rule that a paired quantity gets sub-columns
%      rather than a separator inside one cell.  The one place the count and its
%      share stay together is "1,258 (59.9%)", because a share OF ITS OWN COUNT
%      is not a second statistic.
%
% ---------------------------------------------------------------------------
% WHAT THE RQ2 PROSE MUST NOW CARRY
% ---------------------------------------------------------------------------
% Block (a) now carries a local note for its action partition and outcome
% denominators.  The following population and audit-design facts still belong
% in the body text because they govern the relation between (a) and (b):
%
%   the two populations   (a) is the balanced Full arm, 70 runs / 2,100 captures
%                         at 12MP and 73 / 2,116 at 24MP.  (b) is a DISJOINT
%                         Pacing-only pool, 882 decisions per group at 12MP and
%                         996 Multi-frame / 986 Single-frame at 24MP.  Without
%                         this the two blocks read as one decision set measured
%                         twice, which is the error the split exists to prevent.
%   the audit's design    (b) scores the fresh shadow-model admit/skip decision,
%                         taken before session-sticky demotion, against the
%                         factual outcome; its counts are shares of their own
%                         factual class and sum to 100% within each.
%   the selection caveat  (b)'s 0803 part is a starting-overheat-level subset and
%                         is NOT outcome-neutral; at 24MP the level rule alone
%                         removes that source's entire unsafe-admitted
%                         population.  The block comment above owns the detail.
%   the two medians       Skip margin and skip overrun are medians over the model
%                         skips of that factual class, as a share of the internal
%                         Capture Timeout deadline, whose value is not reported.
%   the group definition  Each capture contributes at most one decision per
%                         optional-work group: Multi-frame = Bokeh, Single-frame
%                         = Filter.
%
% To restore a full-width float, change table -> table* and both \columnwidth
% arguments of \fittabcolsep -> \textwidth; the column widths below are measured
% against 252pt and would then need re-measuring.
%
% ---------------------------------------------------------------------------
% Layout mechanics (same as tables/tab_rq3_pacing_summary.tex)
% ---------------------------------------------------------------------------
% \fittabcolsep solves for the \tabcolsep that lands the outer rules on
% \columnwidth, so the two blocks agree with each other and with the column.
% Its fourth argument is 2 x the number of columns: 14 for both blocks.
% Every p{} width below is the measured maximum of its own data and its own
% header at \scriptsize; a header line wider than its p{} value inside a
% \makecell OVERFLOWS, and a plain cell wider than it silently WRAPS with no
% warning.  Re-measure with \settowidth before changing any label.
%
% (a) sums to 230pt of content in 252pt and (b) to 224pt.  Their solved
% \tabcolsep values therefore stay close enough that the two blocks read as one
% exhibit while (a) retains separate realized-overrun and watchdog columns.
