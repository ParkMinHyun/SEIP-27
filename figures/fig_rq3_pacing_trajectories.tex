% RQ3: Per-shot policy trajectories and backlog-cost comparison for two devices.
%
% S26 Ultra currently renders the collected No-pacing and Ours series; empty
% policy CSVs add no curve until their factual traces arrive.  S26 remains Data
% pending.
%
% Baseline naming follows the implementation
% (patches/rq3-pacing-policy-switch.patch, PolicyType): OURS, THERMAL_LUT,
% QUEUE_EWMA.  The earlier "Static LUT" / "Queue dynamic" labels are retired.
%
% Each policy CSV contains one row per shot and the median, P10, and P90 of
% realized backlog, queue depth, and applied delay.  Only the medians are
% plotted: with four policies in a panel 0.215\textwidth wide, eight band edges
% crossed each other and the medians, and readers could not tell which edge
% belonged to which policy.  The P10/P90 columns stay in the CSVs and the
% per-run spread is released with the artifact.  Each backlog-cost CSV may
% contain multiple parameter settings per policy to draw a frontier.
%
% The S26 Ultra series use the same included runs as
% tables/tab_rq3_pacing_summary.tex: No-pacing from
% 48U_metrics_12MP_normal_0729_AdmitOnly_{1,2}.xlsx (nine runs) and Ours from
% 48U_metrics_12MP_normal_0729.xlsx (eight runs), starting Lv3, 12MP normal.
% Shot 30 carries no delay value because the delay recorded on shot i gates
% shot i+1, so shot 30's delay would fall outside the controlled 30-shot window
% and would pool only the over-length runs; it is nan and discarded by
% unbounded coords=discard.  Backlog and queue depth remain defined at shot 30.
