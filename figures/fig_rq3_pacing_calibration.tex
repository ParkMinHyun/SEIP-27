% RQ3: applied pacing delay against the delay the same admissibility condition
% requires on measured inputs.  Companion to
% Table~\ref{tab:rq3_pacing_calibration}, which carries the summary statistics
% and the full definition of d*.
%
% Panels (a) and (b) are the calibration view: one point per analyzed
% transition with a positive requirement, x the measured requirement d*, y the
% applied delay d, and the dashed diagonal exact calibration.  Above the
% diagonal the controller paced more than the trace required, below it less.
% The +/-100 ms guides are drawn because the caption reports against them: 88%
% and 77% of points clear the diagonal by more than 100 ms, and all but 1 and 5
% of the points below it fall inside them.  100 ms is a fifth of the 497 ms
% median shot-to-shot interval, so it is a tolerance a user could plausibly not
% notice.  An earlier version of this note justified the same number as "roughly
% one frame interval", which is wrong by an order of magnitude -- a frame is
% about 33 ms -- and is corrected here rather than repeated.
%
% ---------------------------------------------------------------------------
% Why the d* = 0 transitions are not plotted here
% ---------------------------------------------------------------------------
% An earlier revision drew them as a hollow column on the vertical axis -- 277
% points in (a) and 278 in (b), 75.3% and 79.9% of the paced transitions -- on
% the reasoning that a reader who cannot see the column cannot judge how much
% of the picture it is.  That reasoning was right about disclosure and wrong
% about where the disclosure belongs.  Two things settle it:
%
%   1. Those points carry no calibration information.  The grammar of these
%      panels is distance from the diagonal, and a point at x = 0 has no such
%      distance; all it shows is the marginal distribution of d.  Rendered at
%      277 overplotted marks on one x it also saturates into a solid bar, so
%      even that marginal cannot be read off it.
%   2. Panel (c) already contains every one of them, quantitatively.  For a
%      transition with d* = 0 the error d - d* is exactly d, so the column makes
%      up most of the positive side of (c).  Removing it from (a) and (b) routes
%      each quantity to the panel whose grammar fits it; it does not remove
%      anything from the figure.
%
% The restriction is therefore declared on the x label, where it cannot be
% mistaken for a hidden filter, and the count plus the pointer to (c) are in
% the caption.  What the column must NOT be labelled, wherever it appears, is
% "unnecessary pacing".  d* is computed on the realized trace, which pacing
% already shaped; removing those delays would deepen the backlog and lengthen
% later Drafts, so the requirement of the unpaced trajectory is at or above d*.
% RQ1(b) supplies the counterfactual directly: with pacing removed the same
% conditions time out.
%
% The caption now makes that case with a measurement rather than with the
% closed-loop argument alone.  On the same eligible set, every one of the 277
% and 278 zero-requirement paced transitions had a positive measured backlog
% (RQ3Pacing.realBacklogMs), a measured time-to-free
% (PacingReplay.realQueueWaitMs) with P10/P50/P90 of 1,925/3,197/4,006 ms in
% 12MP and 1,589/3,069/4,258 ms in 24MP, and realQueueDepth >= 1 on 100% and
% 99.6% of them (median 4 waiting Drafts).  The applied delay covered a median
% 11% and 7% of that measured wait, and stayed below it on 100% and 96.8%.
% d* = 0 therefore does not mean the pipeline was idle; it means the newest
% committed capture's deadline was not yet threatened on a trace pacing had
% already flattened.  Recomputed from the same workbooks and the same run and
% transition eligibility as Table~\ref{tab:rq3_pacing_calibration}; the 12MP
% figures reproduce that table's 1,167 analyzed / 368 paced / 94 required
% exactly, and the 24MP figures come from 1,036 analyzed before the two
% watchdog-truncated transitions are dropped, which do not fall in this subset
% (278 either way).
%
% Positive-requirement points are split by whether admission demoted the
% sequence after the pacing decision was taken, because that is the first
% objection to the surplus: a delay priced for M+S looks over-large once
% admission has removed M from the Draft that ran.  The split answers it with
% data rather than argument, and the answer is that the effect does not run one
% way.  Demoted transitions are 14 of 94 in (a) and 22 of 73 in (b); their
% coverage is 78.6% against 95.0% for undemoted in (a) but 86.4% against 84.3%
% in (b), and their median surplus among paced transitions is higher in (a)
% (416 vs 282 ms) and lower in (b) (243 vs 274 ms).  Coordination therefore does
% not systematically explain the surplus, which is what leaves the
% Draft-duration reserve as the explanation the table reports.  The subsets are
% small, so the split is presented as a marker class to be inspected rather than
% as a table column with statistics.
%
% Panel (c) is the same quantity as a distribution, over the 371 and 351
% transitions where pacing was in play -- the controller applied a delay, or the
% measured requirement was positive, or both.  Two earlier choices were changed
% here and the reasons matter, because both changes are the kind that can be
% mistaken for flattering the data.
%
% Population.  The panel previously ran over all 1,167 and 1,034 transitions.
% Two thirds of those have d = 0 and d* = 0: nothing was applied and nothing was
% required.  They contributed a vertical step at the origin that occupied 69% of
% the y range and recorded only that most captures need no pacing at all, which
% is Table~\ref{tab:rq1_ablation}'s subject rather than this panel's.  Dropping
% them compresses no information about calibration.  Every transition where
% either side is non-zero is kept, including d = 0 with d* > 0 -- the worst
% under-pacing there is, three cases in each condition.  The change moves the
% reported under-pacing rate UP, from 0.6% and 1.1% of all transitions to 1.9%
% and 3.1% of those in play, and makes it visible on the plot instead of a
% hairline against the axis.  That is the honest direction and is the reason the
% smaller denominator is defensible.
%
% Units.  The x axis was in milliseconds, where a surplus of 1,200 ms has no
% scale to be large or small against.  It is now a share of the Capture Timeout
% budget, which is the only scale on which a delay in this system is either.  It
% also makes the panel consistent with the rest of the paper: the State-held
% column of Table~\ref{tab:rq3_pacing_calibration}, the backlog and margin axes
% of Figure~\ref{fig:casestudy_12mp}, and RQ1's Slack P5 are all shares of the
% same budget.  Distribution over the in-play population, as a share of budget:
%   12MP  min -2.9  P50 +4.7  P90 +9.6  P95 +11.2  max +17.1  under-paced 1.9%
%   24MP  min -7.3  P50 +3.7  P90 +10.5 P95 +14.1  max +27.3  under-paced 3.1%
% The -10..30 window clips nothing in either condition.
%
% Axis range.  Both scatter panels use an identical 0-800 by 0-1500 ms box so
% the two conditions can be compared by eye.  The box is no longer square
% because the two axes no longer span the same data: no requirement in either
% panel exceeds 727 ms, while applied delays reach 2010 ms, so a square window
% wide enough for the y data would leave more than half the x range empty --
% which is what the previous 0-1500 square did.  The diagonal is consequently
% not at 45 degrees; it is still the exact-calibration locus, which is what the
% panel is read against.  Two of the 73 plotted points in (b) exceed 1500 ms on
% the y axis (largest 2010 ms) and are clipped; no point in (a) is clipped.
% Panel (c) no longer shares that unit: its axis is a share of the Capture
% Timeout budget over -10..30%, which clips nothing in either condition.
%
% In-plot annotation.  The panels are annotated so that a reader who skims the
% figure gets the reading without the caption.  (a) and (b) carry n and the
% covered percentage in the corner, the diagonal is labelled d = d* on itself,
% and the region below it is tinted and named "under-paced" -- a tint rather
% than a per-region legend, because the direction then needs no decoding and the
% reader can see at a glance that the tinted triangle is nearly empty.  Both
% panels are empty above x = 400, so one placement serves both.
% (c) is deliberately NOT tinted the same way.  There the under-paced region is
% a full-height band left of zero holding 1.9% and 3.1% of the mass, so a tint
% would give it visual weight the data does not have; the arrow in its label
% carries the direction instead.  Its two annotations are the under-paced share
% and the +10%-of-budget guide, which is where 91% and 88% of the distribution
% has been reached.
%
% Point counts: (a) 94 with a positive requirement (80 undemoted, 14 demoted)
% of 1,167 analyzed transitions; the other 1,073 are the 277 with d* = 0 and
% the 796 at the origin, and neither group is drawn here.  (b) 73 (51 and 22)
% of 1,034, with 278 and 683.
%
% Data: data/rq3/calibration/, generated from
% SM-S948U_metrics_{12MP_normal,24MP_memory}_0803.xlsx (ML commit 99aae0a).
% Run and transition eligibility is documented in
% tables/tab_rq3_pacing_calibration.tex and is identical here.

% Layout: single-column float.  A three-panel row across \textwidth was tried
% and dropped -- resized into one column its tick labels fall below four point.
% The panels are therefore stacked, the two scatters side by side on the first
% row because they are meant to be compared with each other, and the error
% distribution on its own wider row because its x range is three times theirs.
% Only panel (a) carries the y label; (b) shares the axis and would only repeat
% it at the cost of the plot box.

\begin{figure}[t]
  \centering
  \providecommand{\rqThreeCalDir}{data/rq3/calibration}

  % Palette: the figure is monochrome apart from one accent.  Circle and diamond
  % are both compact and rounded, so the two classes separate by shape without
  % the visual shout of a triangle, and the accent is a muted teal rather than a
  % saturated blue so it sits quietly against the grey tint below the diagonal.
  \tikzset{
    rq3cal required/.style={
      mark=*, mark size=1.3pt, only marks,
      draw=black!75, fill=black!75, fill opacity=0.5, draw opacity=0.65},
    % There is no second marker class.  An earlier revision split the points by
    % whether admission demoted the sequence after the pacing decision, to answer
    % the first objection to the surplus -- that a delay priced for M+S only
    % looks over-large once admission has removed M.  The split is retired
    % because the objection's answer is a null result and a scatter cannot show
    % one: on the quantity these panels plot, distance from the diagonal, the two
    % subsets are indistinguishable (Mann-Whitney p = 0.62 and 0.66; medians +253
    % vs +290 ms and +250 vs +340 ms).  The only apparent difference, 21.4% of
    % demoted points below the diagonal against 5.0% in 12MP, rests on 3 of 14
    % points and reverses in 24MP (13.6% against 15.7%).  A reader given a second
    % marker class hunts for a pattern that is not there; the finding is one
    % sentence and belongs in the caption, which is where it now is.
    rq3cal diag/.style={black, densely dashed, line width=0.6pt},
    rq3cal band/.style={gray!60, dotted, line width=0.45pt},
    % 0.7pt, not the 1.0pt these curves carried while the figure spanned
    % \textwidth.  Against a 0.35pt axis and a 0.2pt grid the heavier stroke
    % read as coarse once the figure was cut to one column, and the dash needed
    % shortening with it or it broke into visible chunks at this scale.
    % Plotted as connected order statistics rather than with pgfplots'
    % "const plot" step handler.  The step form is the literal ECDF, but the CSV
    % holds every distinct error value, so in the dense middle its risers are
    % below one device pixel while in the sparse tail they become long flats
    % joined by tall jumps -- which is exactly the staircase that read as coarse.
    % The same ECDF points are connected with a low-tension curve.  This removes
    % visible polygon corners in the steep middle without the broad bowing of
    % TikZ's default tension; round caps also keep the short dashed trace from
    % reading as a chain of square blocks at one-column scale.
    rq3cal ecdf a/.style={black, solid, line width=0.7pt, smooth,
      tension=0.35, line join=round, line cap=round},
    rq3cal ecdf b/.style={black!55, line width=0.7pt, smooth,
      tension=0.35, line join=round, line cap=round,
      dash pattern=on 2pt off 1.1pt},
    % Both edges of the shaded band, drawn alike.  Darker than the grid they sit
    % among, because a light rule on the boundary of a fill reads as the edge of
    % the fill rather than as a marked value -- and both are marked values: zero
    % is the exact-calibration locus and +10% closes the band the caption quotes.
    rq3cal band edge/.style={black!45, solid, line width=0.5pt},
  }

  % In-plot annotation, so that the panels carry their own reading without the
  % caption.  The tint below the diagonal is the region where the delay did not
  % cover the requirement; tinting it rather than labelling every region keeps
  % the direction readable at a glance and costs no text.  The same tint marks
  % the same meaning left of zero in panel (c).
  % #1 file stem  #2 point count  #3 percentage with d >= d*
  % fill opacity, not a colour mix.  pgfplots draws the grid before the axis
  % body, so an opaque region fill covers every grid line inside it -- which is
  % what hid them here.  A translucent fill of the same apparent lightness lets
  % the grid through unchanged.
  % Warm for the region where the envelope failed, against the cool band of
  % panel (c) that marks where the error distribution sits: one hue per
  % direction, so no tint means two things across the figure.
  \newcommand{\rqthreecalscatter}[3]{%
    \draw[fill=red,fill opacity=0.07,draw=none]
      (axis cs:0,0) -- (axis cs:800,800) -- (axis cs:800,0) -- cycle;
    \addplot[rq3cal band,forget plot,domain=0:800,samples=2] {x+100};
    \addplot[rq3cal band,forget plot,domain=100:800,samples=2] {x-100};
    \addplot[rq3cal diag,forget plot,domain=0:800,samples=2] {x};
    % Two files, one style: the split they encode is no longer drawn, and the
    % files are left alone so the subset stays available for the audit.
    \addplot[rq3cal required,forget plot]
      table[x=required_ms,y=applied_ms,col sep=comma]
      {\rqThreeCalDir/scatter_#1_req_kept.csv};
    \addplot[rq3cal required,forget plot]
      table[x=required_ms,y=applied_ms,col sep=comma]
      {\rqThreeCalDir/scatter_#1_req_changed.csv};
    % Both panels are empty above x = 400, so one placement serves both.
    \node[anchor=north east,font=\tiny,align=right,inner sep=1.5pt]
      at (rel axis cs:0.98,0.98) {\(n=#2\)\\covered #3\%};
    \node[anchor=south east,font=\tiny,text=red!45!black,inner sep=1.5pt]
      at (axis cs:790,60) {under-paced};}

  \pgfplotsset{
    rq3cal axis/.style={
      scale only axis=true,
      tick label style={font=\tiny},
      label style={font=\scriptsize},
      title style={font=\scriptsize,yshift=-2pt},
      grid=major,
      major grid style={gray!20,line width=0.2pt},
      axis line style={line width=0.35pt},
      tick style={line width=0.35pt},
      tick align=outside,
      tick pos=left,
      enlargelimits=false,
      clip=true,
    },
  }

      rq3cal axis,
      % Only (a) carries the y label, so the separation has to clear one tick

      height=0.35\columnwidth,
      xmin=0,xmax=800,ymin=0,ymax=1500,

      % The two panels share both axes, so each axis is described once: the y
      % label on (a), and the x label as a single centred node under the pair.
      % Repeating "Required delay (ms)" under each box would only say the same
      % thing twice in a figure this small.
      \nextgroupplot[
        title={(a) 12MP normal},

      ]

  \end{tikzpicture}
