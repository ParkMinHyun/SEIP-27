% RQ3: applied pacing delay against the delay the same admissibility condition
% requires on measured inputs.  Companion to
% Table~\ref{tab:rq3_pacing_calibration}, which carries the summary statistics
% and the full definition of d*.
%
% Panels (a) and (b) are the calibration view: one point per analyzed
% transition with a positive requirement, x the measured requirement d*, y the
% applied delay d, and the dashed diagonal exact calibration.  Above the
% diagonal the controller paced more than the trace required, below it less.
% The +/-100 ms guides are drawn because the caption reports against them: 57%
% and 54% of points clear the diagonal by more than 100 ms, and 9 of the 26 and
% 35 of the 57 points below it fall outside them.  100 ms is a fifth of the
% 456 ms (12MP) and 655 ms (24MP) median shot-to-shot interval, so it is a
% tolerance a user could plausibly not notice.  An earlier version of this note
% justified the same number as "roughly one frame interval", which is wrong by an
% order of magnitude -- a frame is about 33 ms -- and is corrected here rather
% than repeated.
%
% Both numbers moved a long way from the previous run set, where 88% and 77% of
% points cleared the diagonal and only 1 and 5 points fell outside the guides.
% The tinted under-paced triangle is no longer close to empty, and any sentence
% written against the old figure -- "the tinted region is nearly empty", "all but
% a handful of deficits are within a tolerance the user cannot notice" -- is now
% false.  See tables/tab_rq3_pacing_calibration.tex for what drives the change.
%
% ---------------------------------------------------------------------------
% Why the d* = 0 transitions are not plotted here
% ---------------------------------------------------------------------------
% An earlier revision drew them as a hollow column on the vertical axis -- 350
% points in (a) and 374 in (b), 85.2% and 79.4% of the paced transitions -- on
% the reasoning that a reader who cannot see the column cannot judge how much
% of the picture it is.  That reasoning was right about disclosure and wrong
% about where the disclosure belongs.  Two things settle it:
%
%   1. Those points carry no calibration information.  The grammar of these
%      panels is distance from the diagonal, and a point at x = 0 has no such
%      distance; all it shows is the marginal distribution of d.  Rendered at
%      350 overplotted marks on one x it also saturates into a solid bar, so
%      even that marginal cannot be read off it.
%   2. Panel (c) already contains every one of them, quantitatively.  For a
%      transition with d* = 0 the error d - d* is exactly d, so the column makes
%      up most of the positive side of (c).  Removing it from (a) and (b) routes
%      each quantity to the panel whose grammar fits it; it does not remove
%      anything from the figure.
%
% The restriction is therefore declared on the x label, where it cannot be
% mistaken for a hidden filter, and the count plus the pointer to (c) are in
% the caption.  What the column must NOT be labelled, wherever it appears, is
% "unnecessary pacing".  d* is computed on the realized trace, which pacing
% already shaped; removing those delays would deepen the backlog and lengthen
% later Drafts, so the requirement of the unpaced trajectory is at or above d*.
% RQ1(b) supplies the counterfactual directly: with pacing removed the same
% conditions time out.
%
% The caption now makes that case with a measurement rather than with the
% closed-loop argument alone.  On the same eligible set, every one of the 350
% and 374 zero-requirement paced transitions had a positive measured backlog
% (RQ3Pacing.realBacklogMs), a measured time-to-free
% (PacingReplay.realQueueWaitMs) with P10/P50/P90 of 1,815/3,091/4,092 ms in
% 12MP and 1,123/3,024/4,472 ms in 24MP, and realQueueDepth >= 1 on 100% and
% 94.1% of them (median 4 waiting Drafts).  The applied delay covered a median
% 12% and 8% of that measured wait, and stayed below it on 99.4% and 95.4%.
% d* = 0 therefore does not mean the pipeline was idle; it means the newest
% committed capture's deadline was not yet threatened on a trace pacing had
% already flattened.  Recomputed from the same workbooks and the same run and
% transition eligibility as Table~\ref{tab:rq3_pacing_calibration}; the 12MP
% figures reproduce that table's 1,920 analyzed / 411 paced / 79 required
% exactly, and the 24MP figures come from 1,863 analyzed before the two
% watchdog-truncated transitions are dropped, which do not fall in this subset
% (374 either way).
%
% Positive-requirement points are split by whether admission demoted the
% sequence after the pacing decision was taken, because that is the first
% objection to the surplus: a delay priced for M+S looks over-large once
% admission has removed M from the Draft that ran.  The split answers it with
% data rather than argument, and the answer is that the effect does not run one
% way.  Demoted transitions are 30 of 79 in (a) and 61 of 140 in (b); their
% coverage is 73.3% against 63.3% for undemoted in (a) but 49.2% against 67.1%
% in (b), and their median surplus among paced transitions is lower in both
% (260 vs 306 ms and 218 vs 400 ms).  The objection predicts the opposite sign:
% if the surplus were an artefact of admission removing M after the delay was
% priced, demoted transitions would carry the LARGER surplus.  They carry the
% smaller one in both conditions, so coordination does not explain the surplus,
% and the Draft-duration reserve remains the explanation the table reports.
% Coverage is the weaker half of this comparison -- 73.3 vs 63.3 in (a) against
% 49.2 vs 67.1 in (b), and on the previous run set both ran the other way round
% (78.6 vs 95.0 and 86.4 vs 84.3) -- so quote the surplus comparison, not the
% coverage one.  The split is presented as a marker class to be inspected rather
% than as a table column with statistics.
%
% Panel (c) is the same quantity as a distribution, over the 429 and 514
% transitions where pacing was in play -- the controller applied a delay, or the
% measured requirement was positive, or both.  Two earlier choices were changed
% here and the reasons matter, because both changes are the kind that can be
% mistaken for flattering the data.
%
% Population.  The panel previously ran over all 1,920 and 1,861 transitions.
% Three quarters of those have d = 0 and d* = 0: nothing was applied and nothing
% was required.  They contributed a vertical step at the origin that occupied
% most of the y range and recorded only that most captures need no pacing at all,
% which is Table~\ref{tab:rq1_ablation}'s subject rather than this panel's.
% Dropping them compresses no information about calibration.  Every transition
% where either side is non-zero is kept, including d = 0 with d* > 0 -- the worst
% under-pacing there is, 18 cases in (a) and 43 in (b).  The change moves the
% reported under-pacing rate UP, from 1.4% and 3.1% of all transitions to 6.1%
% and 11.1% of those in play, and makes it visible on the plot instead of a
% hairline against the axis.  That is the honest direction and is the reason the
% smaller denominator is defensible.
%
% Units.  The x axis was in milliseconds, where a surplus of 1,200 ms has no
% scale to be large or small against.  It is now a share of the Capture Timeout
% budget, which is the only scale on which a delay in this system is either.  It
% also makes the panel consistent with the rest of the paper: the State-held
% column of Table~\ref{tab:rq3_pacing_calibration}, the backlog and margin axes
% of Figure~\ref{fig:casestudy_12mp}, and RQ1's Slack P5 are all shares of the
% same budget.  Distribution over the in-play population, as a share of budget:
%   12MP  min -8.3  P50 +4.8  P90 +10.6 P95 +11.7  max +31.5  under-paced 6.1%
%   24MP  min -13.1 P50 +3.5  P90 +11.6 P95 +15.3  max +27.3  under-paced 11.1%
% The window was -10..30 and now clipped both tails -- three points below -10 in
% 24MP and one above +30 in 12MP -- so it is widened to -15..35, which clips
% nothing.  The tick set is unchanged so the zero and +10% band edges still land
% on labelled values.
%
% Axis range.  Both scatter panels use an identical 0-1100 by 0-1500 ms box so
% the two conditions can be compared by eye.  The box is not square because the
% two axes do not span the same data: no requirement in either panel exceeds
% 1038 ms, while applied delays reach 2022 ms, so a square window wide enough
% for the y data would leave a third of the x range empty.  The diagonal is
% consequently not at 45 degrees; it is still the exact-calibration locus, which
% is what the panel is read against.  The x range was 0-800 on the previous run
% set, where the largest requirement was 727 ms; it is widened here because two
% 24MP points now sit beyond 800, and widening is the only option that does not
% drop data.  Three of the 140 plotted points in (b) exceed 1500 ms on the y
% axis (largest 2022 ms) and are clipped; no point in (a) is clipped and no
% point in either is clipped in x.
% Panel (c) no longer shares that unit: its axis is a share of the Capture
% Timeout budget over -15..35%.
%
% In-plot annotation.  The panels are annotated so that a reader who skims the
% figure gets the reading without the caption.  (a) and (b) carry n and the
% covered percentage in the corner, the diagonal is labelled d = d* on itself,
% and the region below it is tinted and named "under-paced" -- a tint rather
% than a per-region legend, because the direction then needs no decoding.  On
% the previous run set the point of the tint was that the reader could see the
% triangle was nearly empty; it is no longer empty, holding 26 of 79 points in
% (a) and 57 of 140 in (b), and the tint now does the opposite work.  Keep it:
% the region it marks is the figure's main negative finding and it should be the
% first thing the eye lands on.  Both panels are sparse above x = 600, so one
% placement serves both.
% (c) is deliberately NOT tinted the same way.  There the under-paced region is
% a full-height band left of zero holding 6.1% and 11.1% of the mass, so a tint
% would give it more visual weight than the share warrants; the arrow in its
% label carries the direction instead.  Its two annotations are the under-paced
% share and the +10%-of-budget guide, which is where 86% and 87% of the
% distribution has been reached.
%
% Point counts: (a) 79 with a positive requirement (49 undemoted, 30 demoted)
% of 1,920 analyzed transitions; the other 1,841 are the 350 with d* = 0 and
% the 1,491 at the origin, and neither group is drawn here.  (b) 140 (79 and 61)
% of 1,861, with 374 and 1,347.
%
% Data: data/rq3/calibration/, generated by scripts/rq3_calibration_metrics.py
% from data/ablation_sampling/48U_metrics_{12MP_normal,24MP_memory}_0803_{1,2}.xlsx
% (ML commit 99aae0a).  Run and transition eligibility is documented in
% tables/tab_rq3_pacing_calibration.tex and is identical here.

% Layout: single-column float.  A three-panel row across \textwidth was tried
% and dropped -- resized into one column its tick labels fall below four point.
% The panels are therefore stacked, the two scatters side by side on the first
% row because they are meant to be compared with each other, and the error
% distribution on its own wider row because its x range is three times theirs.
% Only panel (a) carries the y label; (b) shares the axis and would only repeat
% it at the cost of the plot box.

  % Palette: the figure is monochrome apart from one accent.  Circle and diamond
  % are both compact and rounded, so the two classes separate by shape without
  % the visual shout of a triangle, and the accent is a muted teal rather than a
  % saturated blue so it sits quietly against the grey tint below the diagonal.
  \tikzset{
    rq3cal required/.style={
      mark=*, mark size=1.3pt, only marks,
      draw=black!75, fill=black!75, fill opacity=0.5, draw opacity=0.65},
    % There is no second marker class.  An earlier revision split the points by
    % whether admission demoted the sequence after the pacing decision, to answer
    % the first objection to the surplus -- that a delay priced for M+S only
    % looks over-large once admission has removed M.  The split stays retired,
    % but the reason has changed with the run set and the note is rewritten
    % rather than left to rot.  It was retired as a null result (Mann-Whitney
    % p = 0.62 and 0.66 on distance from the diagonal).  On the balanced run set
    % the difference is larger and one-directional -- p = 0.25 and 0.06, medians
    % +216 vs +199 ms and -4 vs +251 ms -- but it points AGAINST the objection:
    % demoted transitions carry the smaller surplus, where the objection
    % predicts the larger.  A second marker class would therefore invite the
    % reader to look for a confound that the data rules out.  The share of
    % demoted points below the diagonal is 26.7% against 36.7% in 12MP and 50.8%
    % against 32.9% in 24MP, which does not agree in sign between conditions and
    % is another reason not to draw it.  The finding is one sentence and belongs
    % in the caption, which is where it now is.
    rq3cal diag/.style={black, densely dashed, line width=0.6pt},
    rq3cal band/.style={gray!60, dotted, line width=0.45pt},
    % 0.7pt, not the 1.0pt these curves carried while the figure spanned
    % \textwidth.  Against a 0.35pt axis and a 0.2pt grid the heavier stroke
    % read as coarse once the figure was cut to one column, and the dash needed
    % shortening with it or it broke into visible chunks at this scale.
    % Plotted as connected order statistics rather than with pgfplots'
    % "const plot" step handler.  The step form is the literal ECDF, but the CSV
    % holds every distinct error value, so in the dense middle its risers are
    % below one device pixel while in the sparse tail they become long flats
    % joined by tall jumps -- which is exactly the staircase that read as coarse.
    % The same ECDF points are connected with a low-tension curve.  This removes
    % visible polygon corners in the steep middle without the broad bowing of
    % TikZ's default tension; round caps also keep the short dashed trace from
    % reading as a chain of square blocks at one-column scale.
    rq3cal ecdf a/.style={black, solid, line width=0.7pt, smooth,
      tension=0.35, line join=round, line cap=round},
    rq3cal ecdf b/.style={black!55, line width=0.7pt, smooth,
      tension=0.35, line join=round, line cap=round,
      dash pattern=on 2pt off 1.1pt},
    % Both edges of the shaded band, drawn alike.  Darker than the grid they sit
    % among, because a light rule on the boundary of a fill reads as the edge of
    % the fill rather than as a marked value -- and both are marked values: zero
    % is the exact-calibration locus and +10% closes the band the caption quotes.
    rq3cal band edge/.style={black!45, solid, line width=0.5pt},
  }
