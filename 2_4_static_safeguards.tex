\subsection{Limitations of Static Thermal Gating}
\label{sec:guard-limit}
To reduce the draft--final visual gap, the Draft Sequence's optional stages should run on all supported models whenever safely possible, rather than be suppressed uniformly under thermal stress as production does.

\smallskip\noindent\textbf{Production static thermal guard.}
Samsung's overheat level is an ordinal thermal indicator on a 0--6 scale, where larger values denote stronger throttling.
During pre-release validation, level-4 throttling delayed a single-frame Draft stage and caused a Capture Timeout.
After the failure recurred despite optimization, we adopted a uniform safeguard that skips optional stages at level 4 or higher.
Because the Draft Sequence is implemented in framework code shared across models, the safeguard applies uniformly rather than through model-specific branches.
However, level 4 can also occur during ordinary use under high ambient temperatures, charging, or preceding device workloads, so the uniform guard may suppress optional Draft processing even when sufficient capture budget remains.
More fundamentally, the thermal level does not indicate how much of the deadline has already been consumed by queueing or how much Draft work remains.

\smallskip\noindent\textbf{Required runtime control.}
For the target Portrait configuration, we denote the candidate lightweight multi-frame Draft stage by \emph{M} and the deployed optional single-frame stages collectively by \emph{S}.
We compare M with M+S; both are followed by the same mandatory encoding and saving.
We first evaluated M on the Galaxy S26 Ultra because, unlike other flagship variants, it imposes no additional restrictions on parallel capture beyond the static thermal guard.
With M enabled and the guard bypassed, we ran ten 30-capture trials per combination of starting overheat level (0--6), resolution, memory condition, and Draft Sequence configuration.
The motivating level-4 failure occurred near the 20th consecutive capture with 12 Draft Sequences pending, so each trial continued to 30 captures to drive the Draft pipeline beyond the observed failure point.
For memory-pressure tests, we ran the camera alongside AnTuTu Benchmark~11.1.4's memory-stress workload.

Some trials starting at overheat levels 0--3 timed out even though the production guard permits optional stages to run at those levels. 
Conversely, at starting levels 4--6, multiple captures successfully completed optional stages before the first timeout occurred, although the production guard would suppress those stages from the first capture.
Together, these results show that a fixed thermal threshold cannot reliably identify which captures have sufficient budget to execute optional stages.
Neither executing optional stages unconditionally nor adjusting only the current capture's work resolves this mismatch: the former requires wider capture spacing to prevent queued work from consuming later budgets, whereas the latter cannot recover budget already lost waiting for the Draft worker.
Running optional stages reliably therefore requires coordinated runtime control over each capture's Draft work and the timing of subsequent captures.
