\section{Evaluation}\label{sec:evaluation}

We evaluate whether the controller realizes the deadline-constrained,
responsiveness-dominant trade-off of Section~\ref{sec:objective} through
research questions that separate its safety constraint from the two costs it
ranks:

\begin{enumerate}[label=\textbf{RQ\arabic*:}, leftmargin=4.8em]
  \item \textbf{End-to-end effectiveness.} Does joint control prevent Capture
  Timeout while retaining optional stages at an acceptable pacing cost?

  \item \textbf{Control-loop contribution.} Does each control loop contribute
  to that outcome, and does coordinating the two dominate either loop alone?

  \item \textbf{Admission decision quality.} Does admission execute an optional
  stage when it can finish within the remaining budget and reject it when
  execution would exceed that budget?

  \item \textbf{Pacing-delay sizing.} Does the Budget-Aware Draft Controller
  compute an appropriately sized capture-availability delay for the Draft
  backlog and the remaining Capture Timeout budget?
\end{enumerate}

Section~\ref{sec:setup} states the setup the four share; each research question
then adds only the population and the labelling rule it needs.

\subsection{RQ3: Admission Decision Quality}
RQ3 labels each decision retrospectively from the realized trace.
A decision is \emph{feasible} when the measured duration from that stage through Draft completion fits the \(R_{i,j}\) the decision read, and \emph{unsafe} when it exceeds that budget or the watchdog intervenes.
The pair is the realized counterpart of Equation~\ref{eq:admission}, which the runtime tests against \(U\) precisely because the realized duration is not yet available.
Because the always-admit arm enforces no skip, its labels record model misjudgement rather than outcomes an enforced build would produce.
