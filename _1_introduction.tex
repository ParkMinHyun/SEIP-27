\section{Introduction}

\label{sec:introduction}

The Samsung Galaxy camera publishes an initial user-visible image, the \emph{draft image}, for each capture and later replaces it with the final image from post-processing.
Samsung refers to the processing stages that produce the draft image as the \emph{draft sequence}.
For selected shot modes, post-processing is deferred until the application enters the background.
The draft image then remains the user-visible result throughout the foreground session, making its visual quality more important.
To narrow the draft--final visual gap, Samsung implemented lightweight multi-frame composition in the draft sequence.

However, Samsung has not deployed this feature on any device model because its added processing can violate the \emph{Capture Timeout}, a fixed deadline for producing each draft image.
A violation crashes the application by design and blocks the release.
Parallel capture makes this risk worse.
It lets the application accept the next shutter input before the preceding draft image is produced, shortening the shot-to-shot interval.
Draft sequences still execute one at a time on a single draft worker, so processing added to one capture also consumes the timeout budget of every capture queued behind it.

Samsung introduced a static thermal guard during pre-release validation to mitigate this risk, but it cannot distinguish safe captures from unsafe ones.
The guard skips the optional stages of the draft sequence once the device's overheat level reaches 4 on a 0--6 scale, but this level reflects neither how long a capture has waited nor how much draft work remains.
Indeed, in our motivating experiment with the guard bypassed, the earliest Capture Timeout at the same starting level varied with resolution, memory pressure, and enabled stages (Section~\ref{sec:guard-limit}).
Deploying lightweight multi-frame composition therefore requires deciding at run time whether each capture's remaining draft work fits within the remaining timeout budget.

The draft pipeline can neither reject an accepted capture nor preempt a running stage.
Skipping optional stages can shorten processing but cannot recover time already spent waiting, so the next capture must sometimes be delayed as well.
These two levers correspond to workload control~\cite{approxdet-sensys,timecard-sosp} and arrival control~\cite{seda-sosp,breakwater-osdi}, respectively.
Because waiting and processing consume the same per-capture timeout budget, these levers must be coordinated.

We therefore present the Budget-Aware Draft Controller.
A major challenge is determining how much time to reserve for execution overruns without relying on deadline-miss feedback: even a single Capture Timeout blocks the release.
\emph{Remaining-Sequence Admission} admits an optional stage when the capture's remaining timeout budget covers the estimated duration of the entire remaining draft sequence together with a safety margin calibrated from recent stage overruns.
\emph{Capture-Availability Pacing} delays the next capture when the draft work predicted through that capture, adjusted for admission decisions, exceeds the remaining timeout budget.

Experimental results on two commercial devices show that the controller enables lightweight multi-frame composition without Capture Timeout.
Across 28 combinations of device, capture condition, and starting overheat level, every controller run completed all 30 captures without Capture Timeout, whereas running every optional stage without the guard timed out in 26 combinations.
In combinations starting at overheat level 4 or higher, where the guard would skip optional stages, lightweight multi-frame composition still executed on an average of 5.2--22.2 of 30 captures per run.
In the production-default 12MP configuration without memory pressure, pacing added no delay during the first five captures at any starting overheat level below 4.
In an ablation at starting overheat level 4, only the full controller completed every capture on time in all three combinations tested.
It also executed optional stages more often than admission alone.
In an audit of admission decisions, the controller admitted only 5 of 178 unsafe decisions, whereas naive duration estimates admitted 14--42 or skipped 60\% more feasible decisions.
The controller is now undergoing release validation for a forthcoming Galaxy flagship smartphone line.

\smallskip\noindent\textbf{Contributions.}
\begin{itemize}[leftmargin=1.2em]
  \item We characterize how serialized draft execution under parallel capture creates a cross-capture deadline problem for lightweight multi-frame composition, and why a static thermal guard does not reflect per-capture deadline safety.
  \item We present the Budget-Aware Draft Controller, which coordinates remaining-sequence admission with capture-availability pacing. To our knowledge, this is the first work to combine these controls in a production camera system under a hard per-capture deadline.
  \item We evaluate the controller on two commercial devices, examining end-to-end effectiveness, component contribution, admission decision quality against naive approaches, and pacing under queue pressure.
\end{itemize}
