\subsection{Capture-Availability Pacing}
\label{sec:pacing}

\emph{Pacing} maintains a running forecast of draft workload to regulate the next capture opportunity.
It extends this forecast after each decision and rebases it as draft sequences complete.

\smallskip\noindent\textbf{Delay rule.}
When the \texttt{captureAvailable} callback for capture \(i\) is ready for delivery, \(\mathit{pacing}.\textsc{DecideDelay}\) (Algorithm~\ref{alg:overview}, line~\ref{alg:ov:pacing}) computes the next-capture delay as
\begin{equation}
  \mathit{delay}_i
  =
  \left\lceil
    \frac{
      \max\{0,\hat B_i+2\hat R-T_{\mathrm{queue}}\}
    }{2}
  \right\rceil.
  \label{eq:pacing}
\end{equation}

In Equation~\ref{eq:pacing}, \(\hat B_i\) denotes the processing-time backlog predicted by pacing.
Pacing maintains \(\hat t_{\mathrm{drain}}\), the predicted drain time obtained by accumulating point estimates of the draft work in this backlog.
At the pacing decision time,
\begin{equation}
  \hat B_i
  =
  \max\{0,\hat t_{\mathrm{drain}}-\mathit{now}\}.
  \label{eq:backlog}
\end{equation}

The backlog \(\hat B_i\) does not yet include capture \(i\)'s draft work or that of capture \(i+1\), which the current callback enables.
Pacing therefore reserves a duration \(\hat R\) for each.
Let \(\mathcal K^{\mathrm{adm}}\) denote the configured sequence \(\mathcal K\) after removing optional work disabled by admission.
Pacing computes the sequence reserve from the latest timing state as
\begin{equation}
  \hat R
  =
  \max\!\left(C_\tau,\hat P(\mathcal K)\right)
  -
  \left[
    \hat P(\mathcal K)-\hat P(\mathcal K^{\mathrm{adm}})
  \right],
  \label{eq:reserve}
\end{equation}
where \(C_\tau\) is the recency-weighted \(\tau\)-quantile of completed draft-sequence durations.
The controller computes \(\tau\) from this duration history using the effective-sample-size rule in Section~\ref{sec:admission}.
Because \(C_\tau\) can still reflect sequences measured before optional work was disabled, the subtraction removes the predicted cost of such disabled work.
This adjustment removes only the modeled cost of disabled work while retaining historical headroom above the configured-sequence point estimate.

\(T_{\mathrm{queue}}\) denotes the remaining timeout budget of the most recently enqueued capture.
At the pacing decision point, capture \(i+1\)'s timeout clock has not yet started; \(T_{\mathrm{queue}}\) therefore serves as a queue-level pressure reference rather than capture \(i+1\)'s feasibility deadline.
Thus, \(\hat B_i+2\hat R-T_{\mathrm{queue}}\) measures the amount by which the projected draft work exceeds this queue-level budget.
Finally, pacing uses only half of this excess to avoid converting the full excess into irreversible shot-to-shot latency; admission independently evaluates each capture at its optional-stage decisions.
This split is a coordination heuristic, not an optimality claim.

\smallskip\noindent\textbf{Backlog extension.}
Pacing provisionally extends \(\hat t_{\mathrm{drain}}\) after each decision so that a subsequent pacing decision accounts for capture \(i\) before its draft sequence enters the queue.
It uses \(\hat P^{\mathrm{last}}\), the latest point estimate of \(\mathcal K^{\mathrm{adm}}\):
\begin{equation}
  \hat t_{\mathrm{drain}}
  \gets
  \max\{\hat t_{\mathrm{drain}},\mathit{now}+\mathit{delay}_i\}
  +\lceil\hat P^{\mathrm{last}}\rceil.
  \label{eq:clock-update}
\end{equation}
The \(\max\) term places the provisional work after both the existing drain forecast and the callback release time; it does not constrain the actual draft start.
Pacing records the stages represented by the extension so that their predicted cost can be revised at a later rebase.

\smallskip\noindent\textbf{Backlog rebase.}
Pacing rebases the backlog at each draft-sequence completion because provisional extensions use earlier predictions that can become stale as new durations are observed.
After the shared predictor and admission update their states, \(\mathit{pacing}.\textsc{RebaseBacklog}\) (Algorithm~\ref{alg:overview}, line~\ref{alg:ov:pa-rebase}) refreshes the estimate used for future extensions.
Using \(\mathcal K^{\mathrm{adm}}\) for the completed capture, it updates
\[
  \hat P^{\mathrm{last}}
  =
  \hat P(\mathcal K^{\mathrm{adm}}).
\]
Pacing then rebuilds \(\hat t_{\mathrm{drain}}\) from \(\mathit{now}\) by re-estimating the stages recorded for captures whose pacing decisions have occurred but whose draft sequences have not yet started.
Re-estimating the recorded stages preserves the workload represented by each provisional entry; rebase updates its predicted cost rather than retroactively changing which stages it represents.
When the draft queue drains, pacing clears these queue-scoped estimates and decision records while retaining the shared timing history.
